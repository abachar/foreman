# product — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-25 | Single user (the author), no release in v1 | Homebrew release from the start | Iterate fast without a compatibility constraint |
| 2026-08-25 | One window = one folder = one workspace (IDE model) | A single window with several workspaces; a workspace across several windows | Simple mental model, state isolation |
| 2026-08-25 | Center zone = tree of H/V splits, leaves = tab groups (a reused component) | Tabs only in v1 | Real need for terminals side by side; a single component avoids duplication |
| 2026-08-25 | Persistence and restoration of the workspace state | Start from scratch on every open | Daily comfort |
| 2026-08-25 | Local execution only, no distribution in v1 | Signed/notarized DMG | Useless for personal use; deferred |
| 2026-08-25 | State persisted in `<workspace>/.wraith/state.json`; `.wraith/` is the workspace's local config folder | `~/Library/Application Support/Wraith/<hash>` | State tied to the folder, visible, and versioned or ignored as the user chooses |
| 2026-08-26 | **Agentic** positioning: CLI agents are first-class citizens (dedicated buttons, one tab per agent), distinct from `run` commands | Pure "terminal-first", agents = one shell among others | This is the main intended use; an agent is not a user-defined command |
| 2026-08-26 | **No free-form shell**: no terminal tab on the user's initiative; terminal surfaces host agents and runs only (one tab = one process, not a shell); an empty group = the home screen (IntelliJ style) | Terminal-first with `cmd+t` = new shell (decision of 2026-08-25); a shell that can be opened but not by default | Wraith is not a terminal emulator; `cd`/`ls` happen elsewhere, the agent does the work |
| 2026-08-26 | Deployment target = the latest stable macOS (26), the Xcode project is the source of truth, App Sandbox disabled | macOS 15; SwiftPM alone | A single user on the latest version; Liquid Glass and Swift 6.2 natively; a real `.app` (bundle, `open -a`) requires Xcode; the sandbox blocks disk and processes |
| 2026-08-26 | Native toolbar owned by the layout, filled by the features (agents on the left, Run on the right) | Everything through the keyboard/palette; buttons inside the panels | The most frequent actions deserve a click; a single, declarative surface |
| 2026-08-25 | No "scratch" workspace: without an argument, the workspace is `$HOME` (like a shell) | A window without a folder | Uniform model: always a root folder |
| 2026-08-26 | Opening from the CLI: `cli/wraith` = `open -a Wraith <folder>`, received by `application(_:open:)`; a folder passed directly to the binary is still accepted | `wraith://open?path=` URL scheme; launching the binary directly | Zero opening code to write: `open -a` launches or activates the app and hands it the folder; a URL scheme would add encoding in the script and a second entry point |
| 2026-08-27 | v1 distribution = `cli/release`: a local `Release` archive copied into `/Applications`, unsigned, Gatekeeper's one-time prompt accepted by hand | `-exportArchive` with Developer ID; a Homebrew tap; auto-update | R10 and one machine: the archive's `.app` is the product; signing would need an account for nothing. Reopened the day a second machine appears |
| 2026-08-26 | `Info.plist` declares `public.folder` in `CFBundleDocumentTypes` (Viewer role) | No declaration, `open -a` alone | LaunchServices must know that Wraith opens folders; this is also what allows dropping a folder on the icon, through the same entry point |
| 2026-08-28 | **System window restoration disabled** (`restorationBehavior(.disabled)`) | Leaving SwiftUI's restoration on | It re-created a `$HOME` window at every launch next to the folder's window, one more per launch; Wraith restores its own windows from `state.json` (R1, R8) |
