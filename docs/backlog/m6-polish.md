M6 = **closing what is still hanging**. No new feature and **no study of its own**: this file is assembled from the points left open by M0–M5 (the "What is waiting for another milestone" and "To decide" sections of `docs/backlog/m*.md`), from the `questions.md` entries still marked `[ ]`, from the "Open points" of [`shortcuts.md`](../shortcuts.md) and from [`product`](../specs/product/00-study.md)'s out-of-scope list. Every point recorded lands here in a task, or in the **Left out of v1** section with its reason.

Domains touched: none of its own. Every task that changes a behaviour updates the spec of the domain concerned and dates its decision, in the same commit (`AGENTS.md`).

The **Library / native** column is mandatory (`AGENTS.md`). The **Tests** column: what is tested, nothing else — M6 is mostly measurement, configuration and confirmation in use; many rows are therefore a deliberate "—", with the manual check described.

## Verified before M6 (2026-08-27, on the repository at `main` 2bf4f0e)

- **`ShortcutRegistry`** (`Wraith/Layout/ShortcutRegistry.swift`): `register(_:)` **refuses an id that is already taken** (a `fault` log) and **has no unregistration**; `rebuild()` rebuilds the whole table on every change; `ShortcutProblem` (`conflict`, `reservedByLayout`, `invalidOverride`) is exposed through `problems` and shown as a banner by `WorkspaceView` (`Wraith/App/WorkspaceView.swift`). **The registry knows nothing about macOS's own shortcuts**: `startMonitoring` installs an `NSEvent.addLocalMonitorForEvents(matching: .keyDown)`, which sees the event **after** the system has served its own shortcuts. A system conflict is therefore not detectable in code: it has to be found by hand.
- `ShortcutScope` = `global | tab(kind:) | panel | terminal`. **`.panel` is not parameterised by `PanelID`**: two `.panel` actions on the same shortcut cancel each other out (`overlap` compares scopes by equality). M4 and M5 work around it by keeping `cmd+enter` native to their field; that is the only known case today.
- **Repository**: `default.profraw` is **tracked by git** (`git ls-files` lists it) — a coverage artifact, which `coding-rules` forbids committing and which `.gitignore` does not cover.
- **CI** (`.github/workflows/ci.yml`): `xcodebuild test -scheme Wraith -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO`. It is **missing `-skipPackagePluginValidation`** and the `xcodebuild -downloadComponent MetalToolchain` step, both required by `AGENTS.md` since M2 (the `SwiftTermBuildInfoPlugin` plugin, SwiftTerm's Metal renderer): the CI command cannot pass as it stands. `maxim-lobanov/setup-xcode@v1` with `xcode-version: "27"` has never been checked on a runner (`m0-shell.md`, 0.1; `backlog/README.md`: "CI on Xcode 27 unverified").
- **The root README**: its "Roadmap and Status" table lists M0 as `🟡 specs` and M1–M6 as `⚪`, and cites `HighlightService` / `PaletteService`, names that were abandoned (the shared folders are called `Highlight/` and `Palette/`). It has been wrong since M0; `docs/backlog/README.md` is the up-to-date table.
- **Performance budgets** (`architecture.md`, the *Performance* section): a workspace opened in < 500 ms to the first frame, a panel in < 100 ms, typing with no synchronous work. **No measurement exists in the repository**: no performance test, no number quoted in a commit or a backlog.
- **`ThemeService`** (`Wraith/App/ThemeService.swift`): font, size, `light`/`dark`/`system` mode, two ANSI palettes, highlighting role colors. Nothing else. The visual redesign and the tokens are **M8**, not M6.
- **Code formatting**: absent from the code and removed from `editor`'s out-of-scope list by **M7**, not by M6.
