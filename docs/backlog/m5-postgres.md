# M5 — Postgres

M5 = **exploring a database without leaving the workspace**: the `postgres` feature (`Postgres/`), one connection per workspace described in `.wraith/config.json`, the password in the Keychain. Right panel `postgres.schema` (`cmd+shift+b`, see "To decide"), bottom panel `postgres.query` (SQL editor + grid). By the end of M5, the schema panel expands a database's tables, `cmd+enter` runs the selected query, the grid fills as a stream, and the history brings back what was run.

Domains covered: [`postgres`](../specs/postgres/); complements to `Highlight/` (the `sql` grammar, deferred from M1) and to `Workspace/` (`SecretStore`, which does not exist yet).

The **Library / native** column is mandatory (`AGENTS.md`). The **Tests** column: what is tested, nothing else — **no test talks to a server** (`coding-rules`: hermetic, no network). Everything that needs a real database is gathered in the manual verification task 5.9.

## Verified before M5 (2026-08-27, on the code of `main` 2bf4f0e and on the upstream repositories)

**What Wraith already has**, re-read on disk:

- **Shortcuts** — `ShortcutScope = global | tab(kind:) | panel | terminal` (`ShortcutRegistry.swift`). **`.panel` is not parameterised by `PanelID`**: it means "a panel, any panel, has the focus". Two `.panel` actions on `cmd+enter` (`git` R10's commit and `postgres` R10's execution) would **destroy each other** (`ShortcutRegistry.rebuild`: the same scope + the same shortcut → neither is bound). Both therefore stay native keys of their own field, like the palette: `shortcuts.md` already marks them `native`.
- `cmd+.`: `run.stop` is registered with the `.terminal` scope (M2). `postgres` R13's cancellation is in a panel, a disjoint scope: no conflict, and it stays native to the panel anyway.
- **`cmd+shift+d` is `layout.split.horizontal`'s shortcut**, declared `isLayout: true`: `ShortcutRegistry.rebuild` refuses the default of a feature that claims it (`ShortcutProblem.reservedByLayout`, the action is **not** bound) and `WorkspaceView` shows the error. `postgres.schema`'s default must therefore change before M5 — settled below.
- **`cmd+opt+h` (`postgres` R20, the history panel) has no row in `shortcuts.md`**, and it is the macOS system shortcut *Hide Others*. To be handled in 5.8.
- **Workspace** — `WorkspaceConfig.section(_:as:)`, `configChanges()` (one stream per consumer), `setState(_:to:)` debounced at ~1 s, `Workspace.root`. The `password` key is stripped from the config at read time, at any depth, with a warning (`WorkspaceConfig.swift:83`): `config` R11 is already satisfied, `Postgres/` has nothing to filter.
- `Workspace` **exposes no path for `.wraith/`** other than `WorkspaceConfig.file(under:)`; `.wraith/` is only created at the first write of `state.json` (config R1). `.wraith/postgres-history.json` (R20) is therefore written by the feature, which creates the folder if needed.
- **`SecretStore` does not exist**: no file, no `import Security` in `Wraith/`. M5 creates it (task 5.2).
- **Highlight** — `Highlighter.attach(to: NSTextView, language:) -> TextViewHighlighter?` (`Wraith/Highlight/Highlighter.swift`): that is indeed the way for a live editor, so for the SQL editor. `Language` (`Language.swift`) has 14 cases and **no `sql`**: to be added (task 5.4). `Highlighter` is created by `EditorFeature` today; M4 moves it up into `WorkspaceView` — if M4 has not landed, M5 does it.
- **Editor** — `EditorTextView` (`Wraith/Editor/EditorTextView.swift`) is tied to `EditorTab` and `FileDocument`: it is **not reusable** for the SQL editor, in line with the decision of 2026-08-26 (a text area of the feature's own). On the other hand `TextEditing` (`Wraith/Editor/TextEditing.swift`, a `nonisolated enum` of pure functions: `detectIndent`, `newline`, `indent`, `toggleComment`, `moveLines`, `location(ofLine:)`) and `LineNumberRulerView` are reusable as they are — `cmd+/` with the `--` prefix and the indentation do not have to be rewritten.
- **Palette** — `Palette.present(_:over:)` and `PaletteSource` exist; M5 does not use them (the schema filter is a field in the panel).
- **SPM dependencies** (`Wraith.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`, 24 packages): **PostgresNIO is not there**, and neither is `tree-sitter-sql`. `swift-collections` 1.6.0 is already there (pulled in by Neon). The task that adds PostgresNIO **modifies the `pbxproj`** and says so in its commit; likewise for the `sql` grammar.

**PostgresNIO**, read on the upstream repository (`github.com/vapor/postgres-nio`), not from memory:

- Latest tag **1.33.1** (2026-07-17), `swift-tools-version:6.1`, macOS 10.15+. It pulls in **nine transitive dependencies**: swift-nio, swift-nio-ssl, swift-nio-transport-services, swift-crypto, swift-atomics, swift-collections (already there), swift-log, swift-metrics, swift-service-lifecycle. It is by far the heaviest dependency in the project; to be said in the commit that adds it (`AGENTS.md`).
- `PostgresConnection.connect(on: any EventLoop = PostgresConnection.defaultEventLoopGroup.any(), configuration:, id:, logger:) async throws -> PostgresConnection`: **no `EventLoopGroup` to own**, the library provides one by default. `close() async throws`, `closeGracefully() async throws`.
- `PostgresConnection.Configuration.TLS`: `.disable`, `.prefer(NIOSSLContext)`, `.require(NIOSSLContext)` — R1's `sslmode` maps onto it directly, at the price of an `NIOSSLContext(configuration: .clientDefault)` (swift-nio-ssl).
- `PostgresConnection.query(_ query: PostgresQuery, logger:) async throws -> PostgresRowSequence`; `PostgresRowSequence` is an `AsyncSequence` with back-pressure (`AdaptiveRowBuffer`): **R12's streaming does exist**. `PostgresQuery(unsafeSQL: String, binds:)` carries the user's SQL as is, and `ExpressibleByStringInterpolation` binds the parameters for SQL generated by Wraith (R15).
- **The spec's `simpleQuery` does not exist as R10 assumes.** What exists is `PostgresDatabase.simpleQuery(_:)`, the old `EventLoopFuture` API, and it merely calls `query(_:onRow:)`, which builds a `PostgresQuery(unsafeSQL:)`. The modern path always goes through the **extended protocol** (`PostgresChannelHandler`: Parse / Describe / Bind / Execute on the unnamed statement): the simple protocol, the only one that accepts several statements in a message, is exposed nowhere. Postgres refuses several statements in one `Parse` (`42601`). **R10 and R17 are therefore to be amended** — the proposal is in "To decide".
- **`Task.cancel` does not send the protocol's cancel request.** The encoder knows how to build it (`PostgresFrontendMessageEncoder.cancel(processID:secretKey:)`) but it is `internal`; cancelling a running query goes through `ExtendedQueryStateMachine.cancel()`, which moves the stream into the `.drain` state: the rows are **discarded client-side**, the server keeps working. **R13 is wrong on that point** and R12 ("the query is then cancelled") with it — the proposal is in "To decide".

**tree-sitter-sql** (`github.com/DerekStride/tree-sitter-sql`), re-read upstream: latest tag **v0.3.11** (2025-10-01). Its `Package.swift` (tools 5.3) **no longer** contains the deprecated `.package(name:)` that got it dropped in M1 (editor decision 2026-08-26): it declares `.package(url: "https://github.com/tree-sitter/swift-tree-sitter", from: "0.8.0")`, used **only by its test target**. The header `bindings/swift/TreeSitterSql/sql.h` does declare `tree_sitter_sql()`, and `queries/highlights.scm` is copied as a resource (bundle `TreeSitterSql_TreeSitterSql`). **Not verified for lack of a build here**: that Xcode 27 does prune the test dependency and that the package compiles under Swift 6 — that is the first job of task 5.4, and its plan B is written down.

**Spec**: `postgres` R1 and R12 cited the global config removed by the config decision of 2026-08-26 → corrected in 5.1. R10, R12, R13 and the technical options described PostgresNIO capabilities that do not exist → corrected in 5.1, with dated decisions.

### Manual verification checklist (task 5.9)

1. First connection: the password asked once, saved in the keychain, found again when the workspace reopens; a wrong password → the entry invalidated and asked again.
2. `~/.pgpass` at `0600`: connection with nothing typed; the same file at `0644`: ignored with a warning.
3. `sslmode` `disable` / `prefer` / `require` against a TLS server and against a server without TLS.
4. Fully expanding a real database's schema (schemas, tables, views, mat views, functions, sequences, types; columns, indexes, constraints, incoming FKs); a database with several thousand tables; an extension type (PostGIS) rendered as text.
5. A `SELECT` of a million rows: the grid fills page by page, the app stays responsive, stopping at 50,000 rows shows the warning, and **`pg_stat_activity` shows that the query really stopped on the server**.
6. *Stop* / `cmd+.` on a `pg_sleep(60)`: the query disappears from `pg_stat_activity` immediately.
7. `statement_timeout`: a query longer than the bound fails with the server's message.
8. Read-only session: an `UPDATE` fails with `25006` and the banner points at the toggle; with the toggle on → the `UPDATE` goes through; the toggle does not survive closing the panel.
9. Two statements in the buffer: the `42601` error explained; selecting a single statement → it goes through.
10. CSV and JSON export of a result containing `NULL`, `\t`, `\n`, `"`, some `jsonb` and some `bytea`; the CSV read back in a spreadsheet.
11. Server unreachable: an error in under 10 s, no retry, the schema already loaded kept greyed out; a connection dropped mid-query → an error and reconnection on the next action.
12. Two windows on the same database: two independent connections.
13. Editing the `postgres` section of `config.json` hot: the old connection is closed, the new database is the one shown.
14. The server versions tested recorded (at least the author's; `pg_catalog` is stable, but the reconstructed DDL is not).

## Definition of done (M5)

- `.wraith/config.json` with `"postgres": { "host": "localhost", "database": "ccoe", "user": "postgres" }`: `cmd+shift+b` opens the schema panel, the password is asked once then found in the keychain, and the schemas and their tables expand level by level.
- Double-clicking a table: `SELECT * FROM schema.table LIMIT 500` runs in the query panel and fills the grid.
- `cmd+shift+q`, a query, `cmd+enter`: rows streamed in pages of 500, the execution time and the row count in the status bar; a selection runs the selection only.
- A query that will not end stops on *Stop*, **on the server side too** (checked in `pg_stat_activity`, 5.9).
- An `UPDATE` fails while *Allow writes* is unchecked; the toggle is not persisted.
- CSV and JSON export of the result; `cmd+c` copies as TSV.
- The history brings back the last queries, pinning keeps them, and no result is written to disk.
- No secret in `.wraith/`, in the logs or in an error message; a `password` key in `config.json` is still ignored with a warning.
- A `.sql` file opens highlighted in the editor (or as plain text, with the reason recorded, when 5.4's plan B applies).
- `xcodebuild test` covers every "Tests" line; **no test connects to a server or to the real keychain**; lint clean; SPM dependencies added: **PostgresNIO** (and its nine transitive ones) and **tree-sitter-sql** — nothing else; the `pbxproj` and `Package.resolved` are modified by 5.3 and 5.4, by nobody else.
- The manual verification checklist 5.9 has been worked through and its result recorded in `postgres/questions.md`.
- `docs/specs/postgres` up to date; `postgres`'s `questions.md` cleared of the shortcut question; `shortcuts.md`: postgres rows 🟢, a `postgres.history` row added.

## To decide during M5 (decisions expected)

- 5.1: **`postgres.schema`'s `cmd+shift+d` against `layout.split.horizontal`** (`postgres/questions.md`, noted 2026-08-26) — **proposal: `cmd+shift+b`**, with `cmd+shift+d` staying with the layout. Reasons: `cmd+shift+d` is a layout shortcut, which a feature cannot take back (`layout` R24, verified in `ShortcutRegistry.rebuild`); `b` reads as *base*, stays near `cmd+shift+q` (*query*) under the same hand, and is taken neither by another `shortcuts.md` row nor by macOS. `cmd+shift+p` is ruled out: it is the command palette in every neighbouring editor, so it is better kept free for M6. `architecture.md`, `00-study.md` and `shortcuts.md` change in the same task.
- 5.1: **`postgres` R10 and R17, several statements** — proposal: **one statement per execution**. PostgresNIO does not expose the simple protocol (verified above); writing a client-side SQL tokenizer has already been rejected (decision 2026-08-26, `architecture.md` P2) and nothing justifies taking it back up. R10 becomes "the selection, otherwise the whole buffer, sent as is as **one** statement"; R17 loses the per-statement result tabs; the `42601` error is explained by a banner inviting a selection. Rejected alternative: driving the simple protocol by hand over the NIO channel — that is rewriting what the library does, for a convenience.
- 5.1: **`postgres` R12 and R13, cancellation** — proposal: `Task.cancel` **plus** `SELECT pg_cancel_backend($1)` sent over a second short-lived connection, with the pid read once at connection time (`SELECT pg_backend_pid()`), then closing the connection if the server does not answer within 5 s. That is ~30 lines and ordinary SQL. Rejected alternative: settling for `Task.cancel` — the server would keep working until `statement_timeout`, which is exactly what R13 promises to avoid. Rejected alternative: reaching into PostgresNIO's `internal` encoder.
- 5.3: **one connection or a pool** — proposal: `PostgresConnection` alone (one per window, R4), not `PostgresClient` (the pool), which needs a live `run()` task and brings nothing to a single consumer. The second connection used for cancellation is opened and closed on demand.
- 5.3: **R1's `options`** — proposal: passed through in `Configuration.options` if the library exposes them at the time of the task, otherwise sent as `SET` at connection time; to be checked on the pinned version before writing the rule.
- 5.4: **the `sql` grammar** — to be rechecked when the task is done: M1's blocker (`.package(name:)`) no longer exists in `v0.3.11`, but resolution under Xcode 27 could not be tested here. The plan B is written into the task: `sql` stays out of `Language`, no dependency patching.
- 5.5: **reconstructed DDL** — proposal: explicitly best effort (a "reconstructed by Wraith, not the server's definition" banner) for tables, views, functions and indexes only; no attempt on composite types or RLS policies.
- 5.8: **`cmd+opt+h`** (R20) — proposal: no default, a button in the panel's header; the id `postgres.history` is registered with no shortcut and the user can give it one in `config.shortcuts`, like `agents.<id>`. `cmd+opt+h` is *Hide Others* on macOS.
- 5.3: **closing after 10 min of inactivity** (R4) — proposal: a `ContinuousClock` timer armed at the end of every query and disarmed at the next one; to be confirmed in use (a database behind a pooler might prefer a faster close).
