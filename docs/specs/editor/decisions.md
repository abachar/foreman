# editor — Décisions

| Date | Décision | Alternatives rejetées | Raison |
|---|---|---|---|
| 2026-08-27 | **Formatage par binaires externes déclarés dans `config.json`** (`formatter: { "<ext>": "<commande>" }`), `stdin` → `stdout`, jamais de chemin passé au formateur | **swift-format** embarqué en librairie SPM ; les deux à la fois | swift-format (`603.0.0`, 2026-06-30, produit `SwiftFormat`) ne formate que du Swift, soit 1 des 14 grammaires de R11, et tire `swift-syntax` ; les autres langages n'ont que des binaires (prettier, black, rustfmt, gofmt, clang-format), tous en `stdin`/`stdout`. Un seul mécanisme, zéro dépendance, ~80 lignes : Wraith lance déjà des process ainsi pour `run` et `agents` |
| 2026-08-27 | Deux déclencheurs seulement : `editor.format` (`cmd+shift+l`) et la sauvegarde si `formatter.onSave` ; un échec de formatage ne bloque jamais une sauvegarde (R31) | Format on type / on paste ; formatage de la sélection ; sauvegarde refusée si le formateur échoue | Un éditeur simple (décision 2026-08-25) ; perdre une sauvegarde parce qu'un binaire manque serait pire que du texte mal indenté |
| 2026-08-27 | Texte remplacé dans la vue en **une seule opération d'undo**, curseur reporté par ligne/colonne (R29) | Réécrire le fichier sur disque et laisser le rechargement de R9 faire le reste | `cmd+z` doit annuler le formatage d'un coup ; passer par le disque perdrait le curseur, l'état `isDirty` et déclencherait la bannière de conflit de R10 |
| 2026-08-27 | Pas de détection automatique du formateur d'un projet (`.prettierrc`, `pom.xml`, `.editorconfig`) | Lire les fichiers de configuration des outils | Même politique que `run` R1 : explicite et prévisible ; la commande de l'utilisateur peut toujours pointer sa propre config |
| 2026-08-25 | Éditeur simple : saisie, undo, indentation, recherche/remplacement dans le fichier, `cmd+s` ; pas de complétion ni LSP | Viewer seul ; éditeur ambitieux (LSP, multi-curseurs) | Éditer un README ou une config sans quitter Wraith ; le gros du code s'édite ailleurs |
| 2026-08-25 | `NSTextView` sur TextKit 2 | Vue custom ; TextKit 1 | Undo/IME/accessibilité gratuits ; Neon s'y attache directement ; à valider par prototype |
| 2026-08-25 | Set large de grammaires (java, kotlin, ts/tsx, js, json, yaml, toml, markdown, sql, bash, swift, html, css, dockerfile) | Set minimal (java, ts, markdown, sql) | Ajouter une grammaire = une ligne de mapping ; autant couvrir le quotidien |
| 2026-08-25 | `cmd+s` explicite, pas d'autosave ; reload silencieux si non modifié, bannière de conflit sinon | Autosave ; jamais de reload | Sûr avec les watchers/builds ; comportement VS Code connu |
| 2026-08-25 | Markdown : bascule source/preview dans l'onglet (`cmd+shift+v`) | Preview côte à côte synchronisée | Simplicité ; le split manuel existe si besoin |
| 2026-08-25 | `cmd+p` fuzzy sur les chemins, index construit à la première ouverture ; `cmd+shift+f` recherche contenu via `rg` (repli `grep`) dans un panneau bas | Index au démarrage ; recherche contenu maison ; pas de recherche contenu | Paresse (`architecture.md` P4) ; `rg` est plus rapide et plus juste (gitignore) que tout ce qu'on écrirait |
| 2026-08-26 | Palette et highlighting sont des dossiers partagés (`Palette/`, `Highlight/`) consommés par l'éditeur ; Neon utilisé tel quel (highlighter attaché à l'`NSTextView`), lib fuzzy SPM pour le scoring | Fuzzy maison ; session de parsing tree-sitter maison dans l'éditeur | `architecture.md` P2 : `run`, `git`, `postgres` en ont besoin aussi ; on ne réécrit pas ce que Neon et une lib fuzzy font |
| 2026-08-25 | Binaire refusé (octet nul / extension) ; > 2 Mo lecture seule sans highlighting ; > 50 Mo refusé | Lecture tronquée | Un éditeur simple n'a pas à gérer les gros fichiers ; refuser vaut mieux qu'un affichage faux |
| 2026-08-25 | Fichier disparu à la restauration : onglet ignoré (tranche la question laissée par `product`) | Onglet vide en lecture seule | Rien à afficher ; `layout` R28 le prévoit déjà |
| 2026-08-25 | Raccourcis de l'éditeur à portée « onglet éditeur actif » (le `ShortcutRegistry` supporte une portée par kind d'onglet) | Raccourcis globaux | `cmd+f`/`cmd+s` ne doivent rien voler à un terminal focalisé |
| 2026-08-26 | Lib fuzzy de `Palette/` = **FuzzyMatch** (ordo-one, 1.0.0) | Ifrit (portage de Fuse) ; scoring maison | Fuse est un Bitap pour texte libre, sans bonus de frontières ; FuzzyMatch est un Smith-Waterman façon fzf/nucleo (camelCase, `_`, préfixe, consécutifs, ranges), Swift 6, zéro dépendance : le scoring de chemins de R17 tel quel |
| 2026-08-26 | **TextKit 2 validé** : Neon `TextViewHighlighter` sur `NSTextView` avec `NSTextLayoutManager` applique les couleurs en rendering attributes sans retomber en TextKit 1 (test `HighlighterTests`) | TextKit 1 | Le prototype prévu au découpage de M1 passe ; rien à adapter |
| 2026-08-26 | Neon et SwiftTreeSitter suivis sur `main` (pas de tag), figés par `Package.resolved` ; mise à jour = commit dédié | Neon 0.6.0 + SwiftTreeSitter 0.9 | Neon 0.6.0 ne compile pas avec SwiftTreeSitter ≥ 0.10 sous Swift 6.2 ; `main` des deux compile et s'accorde |
| 2026-08-26 | `sql` retiré de R11 en M1, revient avec `postgres` (M5) | Fork du package ; target C dans le projet | Le `Package.swift` de `tree-sitter-sql` (`.package(name:)` déprécié) ne résout pas sous Xcode 27 ; on ne patche pas une dépendance dans M1 |
| 2026-08-26 | css 0.23.2, javascript 0.23.1, yaml 0.7.0 épinglés en version exacte | Dernières versions | Leurs manifests récents testent `fileExists("src/scanner.c")` relatif au cwd (faux sous Xcode) et perdent le scanner : symboles `external_scanner_*` manquants au link |
| 2026-08-26 | Markdown : grammaire bloc seule (`TreeSitterMarkdown`), pas l'inline ni les injections de code en v1 | Bloc + inline via `languageProvider` | Suffisant pour le mode `source` ; la preview (R14) colore les blocs de code via `Highlight/` de son côté |
| 2026-08-26 | « Keep open » = `cmd+k` seul | Chord `cmd+k enter` (VS Code) | Le `ShortcutRegistry` ne gère pas les chords ; en ajouter un pour une seule action serait de la sur-ingénierie |
| 2026-08-27 | Gouttière avec numéros de ligne (`NSRulerView` maison, ~80 lignes, sur les fragments TextKit 2) | Sans numéros ; text view tiers (STTextView) | Demandé à l'usage ; rien de natif ne numérote TextKit 2 et un text view tiers remplacerait `NSTextView` pour ça seul |
