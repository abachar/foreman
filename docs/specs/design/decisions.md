# design — Décisions

| Date | Décision | Alternatives rejetées | Raison |
|---|---|---|---|
| 2026-08-27 | Style **IntelliJ « Islands » en Dark** : fond uni sombre, zones en îlots arrondis séparés par des gouttières, barres plates et opaques, onglets plats, un seul accent | Rendu natif macOS 26 (Liquid Glass, toolbar translucide, chrome système) ; thème clair d'abord | L'auteur n'aime pas le rendu 100 % natif et passe ses journées dans cette fenêtre ; un seul utilisateur, donc le goût de cet utilisateur est le critère |
| 2026-08-27 | **Aucune transparence ni matériau système** dans le chrome (R1), une seule exception : l'ombre portée de la palette | `.bar` et matériaux conservés « parce que c'est natif » | La translucidité fait entrer le bureau et les fenêtres du dessous dans la zone de travail ; c'est précisément ce qui est rejeté |
| 2026-08-27 | Les tokens étendent **`ThemeService`**, pas un second service | `DesignSystem` / `TokenStore` séparé | `ThemeService` possède déjà la police, le mode, les palettes ANSI et les couleurs de rôle : un second service serait un second propriétaire des mêmes informations (`architecture.md`, services partagés) |
| 2026-08-27 | Surcharge par la section `theme` de `.wraith/config.json`, clé par token | Fichier de thème dédié ; sélecteur de thème dans l'UI | Une seule source de configuration (`config` 2026-08-26) ; pas d'éditeur de préférences graphique (`config`, hors périmètre) |
| 2026-08-27 | Un seul jeu dessiné en v1 : **`dark`**. `light` existe, de même structure, dérivé mécaniquement et non validé | Deux thèmes dessinés ; supprimer `light` | Dessiner deux thèmes double le travail de validation à l'œil pour un mode que l'auteur n'utilise pas ; supprimer `light` casserait `terminal` R14, déjà livré et testé |
| 2026-08-27 | Les composants natifs de R12 sont **habillés, pas remplacés** | Barre d'onglets, arbre ou split maison pour contrôler le pixel | `architecture.md` P3 ; l'apparence se change avec des couleurs et des métriques, pas en réécrivant `NSOutlineView` |
| 2026-08-27 | La gouttière de R2 est produite par les **diviseurs de `NSSplitView`** peints au fond de fenêtre, pas par des marges dans chaque vue | Marges posées par chaque feature | Une seule ligne de vérité pour l'espacement ; une feature qui oublie sa marge casserait la grille |
| 2026-08-27 | La première tâche de M8 est une **maquette** avant tout code | Coder les tokens puis regarder | On juge un style sur une image, pas sur une liste de couleurs ; la maquette est aussi ce qui départage les deux options de barre d'outils |
