# layout — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-27 | Toolbar: a `center` placement and panel toggles declared by the layout (R30 amended, `design` R15) | Panels reachable by shortcut and menu only | The author wants the panels one click away, on the validated mockups; the toggles belong to the layout since `PanelManager` owns the visibility |
| 2026-08-25 | The left/right/bottom panels frame the whole split tree | Panels per split | Classic IDE model, a single `[side: id?]` state, predictable |
| 2026-08-25 | iTerm-like shortcuts: `cmd+w`/`cmd+1..9` for tabs, `cmd+d`/`cmd+shift+d` for splits, `cmd+opt+arrows` for group focus (`cmd+t` removed on 2026-08-26: no more default tab) | The VS Code set (`cmd+\`, `cmd+N` = group) | The author's habits; iTerm is the reference |
| 2026-08-26 | No default tab kind: a split and the last tab closed both give an empty group with the home screen (IntelliJ style), fed by the features | `cmd+t` = new shell; a grey empty group; `cmd+t` = quick open | `product`: no free-form shell; the home screen recalls the shortcuts and gives access to the agents |
| 2026-08-25 | Moving a tab between groups from the keyboard only (`cmd+opt+shift+arrows`) | Drag and drop in v1; no moving at all | Covers the real need; inter-group SwiftUI drag and drop is expensive to do well — deferred |
| 2026-08-25 | No group zoom/maximise in v1 | `cmd+shift+return` maximises the active group | Not asked for; hiding the panels is enough |
| 2026-08-25 | Only panels are resizable (mouse); splits use fixed equal shares | Resizable splits; keyboard resize | Simplicity: no ratios to persist and no handles in the tree |
| 2026-08-25 | Binary `split/group` tree, pure operations tested without UI | An N-children grid per split | A binary tree expresses every arrangement; collapsing a split = replacing it with the sibling |
| 2026-08-25 | Panel sizes persisted **per slot**, not per panel | Size per panel | A slot has a single visible width; replacing a panel must not make the layout jump |
| 2026-08-25 | Opaque tab payload (a JSON string) serialised/restored by the owning feature | The layout knows the tab kinds | `Layout` knows no domain; each feature persists whatever it wants |
| 2026-08-25 | A shortcut conflict disables both actions and shows an error; a feature cannot override a layout shortcut | First wins; last wins | A silent conflict is worse than a missing shortcut; the user decides in `config.json` |
| 2026-08-25 | A focused terminal receives every key except `cmd+…` shortcuts | Global `ctrl`/`alt` shortcuts | `ctrl`/`alt` belong to the programs in the terminal (vim, tmux, readline) |
| 2026-08-26 | Native toolbar (`NSToolbar`) owned by the layout; features declare their items (`leading`/`trailing`, action or menu, badge); hidden with `cmd+opt+t` | A custom SwiftUI bar; buttons inside the panels; no toolbar | `product` R11: agents and Run deserve a click; the native component gives the macOS style for free |
| 2026-08-26 | Left/right/bottom panels rendered by `NSSplitView` (`NSSplitViewController`, collapsible items); center splits in SwiftUI with equal shares | Manual `GeometryReader` layout with computed frames; `HSplitView`/`VSplitView` | `architecture`: use the platform; the native component handles resizing, minimums and collapsing with no code |
| 2026-08-26 | Feature registration through `struct`s internal to `Layout/` and closures (activate/deactivate/close), with no plugin framework and no event bus | `ForemanKit` + `PluginContext` + `EventBus` (2026-08-25) | `architecture`: a single target, features call each other directly; the contract has only one implementation |
| 2026-08-25 | Window too small: the panels shrink then hide (`right`, `left`, `bottom`) and come back on their own; the persisted size is untouched | Refuse to shrink the window; overwrite the sizes | The center zone wins (`product` R5) without losing the preferences |
| 2026-08-26 | Tab groups = a `TabGroup` value model + a SwiftUI bar, no native tab component | SwiftUI `TabView` (segmented / sidebar), `NSTabView`/`NSTabViewController` (segmented strip, no closing and no scrolling), window tabs `NSWindow.tabbingMode` (one strip per window, not per group) | None of them has rules R13–R14, R23 (insert after the active tab, close → left neighbour, `cmd+9`), nor R16's IDE bar; the model must be pure, testable and persisted (R27) |
| 2026-08-26 | Center zone rendered in pure SwiftUI (`HStack`/`VStack` with equal shares, `Divider`); tab bar and home screen in SwiftUI | Nested, non-resizable `NSSplitView`s | The splits are fixed (R8): no need for the native component; the rendering follows the tree with no synchronisation code |
| 2026-08-26 | Minimum for a group (and for the center): **300 × 150 pt** instead of 400 × 200 | Keep 400 × 200 and enlarge the default window; no minimum at all | At 1100 pt wide, 400 only allowed a single vertical split; 300 gives three without making the groups unusable |
| 2026-08-26 | Shortcut notation: `cmd`, `shift`, `opt`, `ctrl`; `alt` accepted as an alias in `config.json` | Keep `alt` | On a Mac the key is Option (⌥); `alt` is the PC name and was confusing |
| 2026-08-27 | `escape` (focus to the center) declared with the `panel` scope: in the center, the key goes to the content (the editor's find bar) | An `escape` action per feature (refused by R24); a global `escape` | R23 already said so ("from a panel only"); a global action swallowed the key everywhere |
| 2026-08-28 | `cmd+d` **moves the active tab** into the new group and needs at least two tabs (R9 amended) | An empty sibling on the home screen (the rule since M0) | The author: splitting is done to see two of the open tabs side by side; an empty group then asked for a second action every time |
| 2026-08-28 | Panel sizes persisted **per panel** (R18 amended), not per slot | Keeping one size per slot | The author: Git and the Schema share the right slot but do not want the same width; the format keeps its key, the old per-slot entries are ignored |
| 2026-08-28 | Tab context menu with six close actions (R35), through SwiftUI's `.contextMenu` on the tab | Middle-click to close (still out of scope); an `NSMenu` built by hand | The author wants the IntelliJ closing actions; `.contextMenu` is the native menu with no code of its own, and the selection of the tabs to close is a pure function over the group, testable |
| 2026-08-28 | Home screen on two columns: agents + recent on the left, the whole shortcut table on the right (R33 amended); the `actions` home section is dropped | Keeping a curated list of main actions | The author: the list of shortcuts is documentation, and the registry already holds all of it — a curated copy would drift |
| 2026-08-29 | Conditional features (R36): `git`, `postgres` and `run` register their panels, buttons and global shortcuts only with content, and withdraw them when it goes; late registration honours the restored slot | Keeping every panel and showing a "nothing configured" message inside; a hidden toolbar item with the panel kept | The author's workspace with a trimmed `config.json`: three dead buttons and four dead shortcuts on the home screen; the agents and the browser already follow the same rule |
| 2026-08-30 | A menu bar generated from the `ShortcutRegistry` (R37), and every menu shows the shortcut of the action it offers (R37b); key equivalents are displayed, not bound | Hand-written menus; no menu bar at all (keyboard and home screen only); menu items owning the key equivalents | The registry already holds every action, its title and its shortcut: a hand-written bar would be a second source of truth. Displaying only keeps the single capture path of R25 and avoids an action firing twice |
| 2026-08-30 (from use) | The menu bar is `File / Edit / View / Tools / Run`, Foreman's entries appended to the standard menus, and a hand-written map places each action (R37) | One submenu per feature namespace, generated from the registry (tried the same day) | Eight generated submenus plus the native ones overflowed the bar, with 24 entries under *Layout* alone (`Tab 1`…`Tab 9`, `Focus Group` ×4, `Move Tab` ×4) and three identical *Send to Agent*. A menu bar is a map of the app, not a dump of the shortcut table |
| 2026-08-30 | *New Window* (`cmd+shift+n`) removed | Keeping it beside *File ▸ Open…* | Both opened the same folder picker; `cmd+shift+n` goes back to the free list |
| 2026-08-30 | A double click on the empty part of the tab bar and on the home screen opens an untitled tab in that group (R38); the layout calls back a closure the feature set, it names no action id inline | A `+` button at the end of the tab bar; the layout performing `"editor.newFile"` by id | The double click is what every editor teaches and costs no pixel in the bar; a closure is what the codebase already uses between features (`sendToAgent`), and a hardcoded id would make the layout depend on the editor by string |
| 2026-08-30 | The bar's empty part is a sibling view of the tabs, sized by the bar's width | A background layer under the `ScrollView`; the gesture on the whole bar, relying on the tabs to swallow their clicks | A layer under a `ScrollView` never receives the click, and an ancestor gesture would fire on a double click on a tab as well — a sibling has neither problem |
