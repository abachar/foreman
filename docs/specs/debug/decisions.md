# Decisions — debug

| Date | Decision | Rejected | Why |
|---|---|---|---|
| 2026-10-17 | **Foreman is a DAP client, never a debugger**: one adapter per extension in `config.debug`, declared, the way language servers and commands are ([00-study.md](00-study.md) R1) | Driving JDWP or `lldb` directly; detecting the adapter from the project | Every language has an adapter speaking the same protocol (`java-debug`, `lldb-dap`, `js-debug`); `run` R1 and `editor` R35's policy: declared in the config, nothing detected |
| 2026-10-17 | **A session is a command** of `config.commands` with a `debug` object, `arguments` passed verbatim to the adapter's `attach`/`launch` (R2) | A `launch.json`; Foreman's own argument names translated per adapter | The ▶ menu already lists the commands and the Run panel already hosts their output; `editor` R57 (settings verbatim) showed a translation table is a cost for every adapter and a surprise for the user reading the adapter's documentation |
| 2026-10-17 | **Attach first for Java** — the command starts Spring with the JDWP agent, Foreman attaches; launch with `resolveMainClass`/`resolveClasspath` is the last task (R3, M27 27.4–27.5) | Launch first | Attach reuses Run and the `SPRING_*` environment the `ccoe` config already carries and is enough to debug a backend on day one; launch needs the server's resolution and `runInTerminal` on top |
| 2026-10-17 | **The DAP client is written** (~600 lines: envelope, fifteen requests, six events, a session actor), on `JSONRPC`'s `DataChannel` framing and `LSPAny` for the verbatim arguments; no new dependency | `ChimeHQ/DebugAdapterProtocol`; `noellee/SwiftDAP` | Read on 2026-10-17: the first has eight files, three commits (the last "prepare for transfer", 2026-09-14), no release and the server-side `initialize` only; the second is the adapter side, alpha. Neither has a client session; the types are the small part |
| 2026-10-17 | **The client is developed against `lldb-dap` on Foreman's own Debug build**, Java second | Starting on `ccoe-backend` | `lldb-dap` ships in the selected Xcode, needs no install and no bundle, and a breakpoint in `EditorFeature` is checked without leaving the repository — the way the LSP client was developed against `sourcekit-lsp` (editor decision 2026-08-31) |
| 2026-10-17 | **Breakpoints in `state.json`, never in `config.json`** (R4); nothing of the domain written under `.foreman/` | A `.foreman/breakpoints.json` | The author will commit `.foreman/` to share the config; breakpoints are one machine's session, and `state.json` is already the file that never enters git |
| 2026-10-17 | **The paused line in `statusOrange` at the current line's alpha**, the breakpoint dot in `statusRed` (R4, R5) | Two new theme tokens | `design` R6: the status colours already say these two things, as they did for the diagnostics (editor decision 2026-08-31) |
| 2026-10-17 | **A breakpoint moves with the text by the text storage's own edit notification** (`didProcessEditingNotification`, read before the view re-reads its line starts): the line breaks the edit removed and inserted, against the old line starts, shift the lines after it; a line whose break was removed goes; a break typed at a line's start pushes that line down; a whole-text replacement (reload, formatter) moves nothing (R4, M27 27.2) | `shouldChangeTextIn` on the delegate; tracking each breakpoint as a text range | The storage sees every edit, undo included, and the old line starts are already kept for the gutter; the delegate misses undo and programmatic edits, and a range per breakpoint is a second structure to keep in step with the text |
| 2026-10-17 | **The paused line's tint is `statusOrange` at alpha 0.28** (R5, M27 27.2) | The current line's alpha | The current line is the opaque `surfaceSunken`, so there is no alpha to copy; a status colour over the text needs a translucent fill (the diff's tints use 0.16 for the same reason) — still no new token |
| 2026-10-17 | **The banner of R11 is shown by the Run panel under the shown sub-tab's bar** (`RunFeature.banners`, `BannerView` with a dismiss button; cleared at the command's next launch); a `launch` command with nothing to run has no sub-tab and the banner goes on the active editor tab's `message` instead (M27 27.2) | A modal; a toast | `run` had no banner on a sub-tab (`TerminalTabView`'s is for a missing folder and is not shown in the panel); the panel is where the user looks after pressing Debug |
| 2026-10-17 | **`stopped` asks `threads` and `stackTrace { levels: 1 }` and opens the top frame with the caret kept** (`Editor.open(…, revealOnly: true)`: the line is shown only when it is off screen); `scopes` waits for the panel (27.3) (R5, M27 27.2) | Moving the caret to the line | R5: the user may be reading elsewhere |
| 2026-10-17 | **Xcode's keys** for the seven actions (R7) | VS Code's `f5`/`f9`/`f10`/`f11` | The author's other editor is Xcode on this machine; every key is free in `shortcuts.md` on 2026-10-17 |
| 2026-10-17 | **The Angular frontend in the browser is out of scope** | `js-debug` driving Chrome | It is launching a browser Foreman does not own; `browser` R1's page already has Safari's Web Inspector (browser decision 2026-08-28) |
| 2026-10-17 | **The panel is three `HSplitView` columns** — frames, variables, console — under a controls row of its own (continue/pause in one button, over, into, out, stop, then the state in words), the way Problems puts its pills under the tabs (R6, M27 27.3) | Controls in the tab header; an `HStack` of fixed proportions | The header is for the tabs (`design` R17, 2026-10-17); `HSplitView` resizes with the panel for free and lets the author give the console more room |
| 2026-10-17 | **The panel's model is an empty value created with the feature, not at `makeView`** — only its view is lazy; nothing is requested until `begin` (R10, M27 27.3) | A model created by `makeView` | The state line, the stepping shortcuts and the console must follow a session whether or not the panel was ever shown, and the first `stopped` shows the panel; an empty observable object is allocation, not work |
| 2026-10-17 | **The panel is registered when `config.debug` has an entry and a command's `debug.adapter` names one** (`DebugFeature.wantsPanel`), re-evaluated on the config and on `RunFeature.commandsChanged` (R6, `layout` R36) | Registering on the section alone; polling the commands | R2 makes a `debug` naming an undeclared adapter a warning with no debugging; the two sections decode apart and Run publishes its commands independently of Debug's config read, so Run tells when they change |
| 2026-10-17 | **Frames: `levels: 100`, then a *more…* row** asking `startFrame` = frames loaded; there is more when `totalFrames` says so, else when a page came back full. Only the stopping thread's frames are asked at a stop, the other threads' when their section opens (R6) | Asking every thread's stack at each stop | A Spring server has a hundred threads; stopping is the moment the user waits for |
| 2026-10-17 | **Variables: a recursive `DisclosureGroup`, children asked once on the first expansion**; the first scope, when not `expensive`, is opened at the stop (the locals); `indexedVariables` past 100 are paged by 100 with `start`/`count` and a *more…* row; an adapter that answers an empty page ends the paging (R6, M27 27.3) | `OutlineGroup` (a `nil` children key path is a leaf: no arrow, no hook); an `NSOutlineView` | The smallest thing that has the arrow before the children exist; opening the locals is Xcode's behaviour and costs one request |
| 2026-10-17 | **Console: 2 000 lines, the oldest dropped** (`ContentSearch.limit`'s figure); `stderr` in `statusRed`, `console` in `textSecondary`, `telemetry` not shown, the rest plain; an evaluated expression is echoed as `> expr` in `textSecondary` before its answer; an adapter's refusal is appended in `statusRed` (R6) | An unbounded buffer; showing `telemetry` | The Search panel's cap rule; the DAP says `telemetry` is data for the client, not text for the user |
| 2026-10-17 | **`continue`, `next`, `stepIn`, `stepOut` and `pause` take the stopping thread**; the mark and the stack are dropped when one is sent and rebuilt by the next `stopped`, nothing is cached across stops; `pause` before any stop asks `threads` and takes the first (R7) | Waiting for `continued` to clear the mark | `continued` is optional after a step for some adapters; the user's key press is the fact |
| 2026-10-17 | **The four stepping keys are registered while the session is paused and withdrawn otherwise** (`DebugStep.sync`, called on each change of the model's state); `f1`…`f12` become valid `Shortcut` keys (AppKit's `NSF1FunctionKey`…) (R7) | Registering them for the session's life and ignoring them when running | R7: bound to nothing otherwise, so the keys stay free when nothing is paused; the parser knew no function key before this task |
| 2026-10-17 | **The panel comes up with the first `stopped` of a session**, once (`PanelManager.show`, as Run does on a launch); a failure is shown in the state line as well as in the Run banner (R6, R11) | Showing it at the session's start | Attaching to a program that never stops should not take the Run output away from the user |
| 2026-10-17 | **A `server` session ends with R11's banner when its TCP channel closes**, naming the `lsp.<ext>` server ("stopped or restarted"); the adapter lives in `jdtls`' process, so its death closes the socket. `LSPServers` exposes no restart signal, and none was added (R1, R11, M27 27.4) | A restart callback on `LSPServers`/`LSPServer`; polling `isRunning` | Nothing to wire: the session already treats a finished message stream as its end (`DebugFeature.listen`); a restart is a new process, so the old socket is gone either way |
