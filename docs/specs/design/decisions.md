# design — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-27 | The **IntelliJ "Islands" style in Dark**: a flat dark ground, zones as rounded islands separated by gutters, flat opaque bars, flat tabs, a single accent | Native macOS 26 rendering (Liquid Glass, a translucent toolbar, system chrome); a light theme first | The author does not like the fully native rendering and spends their days in this window; a single user, so that user's taste is the criterion |
| 2026-08-27 | **No transparency and no system material** in the chrome (R1), with a single exception: the palette's drop shadow | Keeping `.bar` and the materials "because they are native" | Translucency brings the desktop and the windows underneath into the working area; that is exactly what is being rejected |
| 2026-08-27 | The tokens extend **`ThemeService`**, not a second service | A separate `DesignSystem` / `TokenStore` | `ThemeService` already owns the font, the mode, the ANSI palettes and the role colors: a second service would be a second owner of the same information (`architecture.md`, shared services) |
| 2026-08-27 | Overrides through the `theme` section of `.wraith/config.json`, one key per token | A dedicated theme file; a theme picker in the UI | A single configuration source (`config` 2026-08-26); no graphical preferences editor (`config`, out of scope) |
| 2026-08-27 | One set designed in v1: **`dark`**. `light` exists, with the same structure, derived mechanically and not validated | Two designed themes; removing `light` | Designing two themes doubles the by-eye validation for a mode the author does not use; removing `light` would break `terminal` R14, already shipped and tested |
| 2026-08-27 | The native components of R12 are **dressed, not replaced** | A home-made tab bar, tree or split view to control every pixel | `architecture.md` P3; appearance is changed with colors and metrics, not by rewriting `NSOutlineView` |
| 2026-08-27 | R2's gutter is produced by **`NSSplitView`'s dividers** painted with the window ground, not by margins in each view | Margins laid out by each feature | A single source of truth for the spacing; a feature that forgot its margin would break the grid |
| 2026-08-27 | **Eight mockups validated as inspiration** (`00-mockups/01–08.jpeg`, generated by the author from `00-mockups/mockup-prompts.md`), with three explicit rejections: the second title band (one band only, R14), the toolbar order the generator produced (R15 fixes it: Explorer toggle left, agents centred with their real icons, Run + Database/Git/History toggles right), and `08.jpeg`'s split as two sibling islands (R21: one island, groups separated by a 1 pt line, no inner radius) | A single pixel-perfect target; redoing the images until they match | The gap between one imagined picture and the app was too large to read anything off it; per-scene images settle the style and the author's eye settles the rest |
| 2026-08-27 | **`dark` token values read off the mockups** (sampled, rounded): `windowBackground` `#212328`, `surface` `#36373B`, `surfaceRaised` `#33363A`, `surfaceSunken` `#1E2326`, `separator` `#3D3F44`, `textPrimary` `#DFE1E5`, `textSecondary` `#9DA0A8`, `textDisabled` `#6F737A`, `accent` `#4A86E0`, `accentText` `#FFFFFF`, `statusGreen` `#5FB865`, `statusOrange` `#E0A63B`, `statusRed` `#E5534B`, `statusBlue` `#4A86E0`; diff tints removed `#3A2A2A` / added `#2A3A2C`; `islandRadius` 8, `gutter` 8, `barHeight` 36, `rowHeight` 24, `contentInset` 12 | IntelliJ Dark's own values (`#1E1F22` / `#2B2D30`) | The images are a shade lighter than IntelliJ and the author validated the images; 8.2 freezes them and checks R7 by test, the eye adjusts in 8.3 |
| 2026-08-27 | The toolbar floats on `windowBackground`; its buttons are flat `surfaceRaised` rectangles; the palette sits on a darker `#23262A` (a fifth shade, `surfaceOverlay`, added to the Backgrounds family of R9) | The bar as an island; the palette on `surface` | Both read directly off the mockups (`01`, `02`) |
| 2026-08-27 | Active tab = bottom accent rule (R5 amended); current line highlighted (R22); per-type file icons from Material Icon Theme (R23); panel toggles in the toolbar (R15, `layout` R30 amended) | Top rule; no line highlight; SF Symbols only; shortcuts only for panels | The author asked for each one on the mockups; the icon set is MIT and already SVG, `IconImage` loads SVG |
| 2026-08-27 | The first task of M8 is a **mockup**, before any code | Coding the tokens then looking at the result | A style is judged on an image, not on a list of colors; the mockup is also what decides between the two toolbar options |
| 2026-08-27 | The toolbar stays a **dressed `NSToolbar`** (option A of the study): `titlebarAppearsTransparent`, `window.backgroundColor`, `toolbarStyle = .unifiedCompact`, `isBordered = false`, a view per item | Option B, a SwiftUI bar replacing `NSToolbar` | The author prefers keeping the native component for the control it gives over window behaviour (full screen, dragging, traffic lights) at a few lines' cost; `layout` R30 and `architecture.md` stay true. B remains the fallback if A leaves a material or separator that cannot be turned off, and would then be a new dated decision |
| 2026-08-27 | The active group's accent border (R3, `layout` R17) is drawn **only when the centre holds more than one group**, as a rounded stroke following `islandRadius` | A permanent rectangle around the centre; a square stroke over the island's rounded corners | The first visual review of M8 (the author's eye, 2026-08-27, mockup `01`): a lone group has nothing to be told apart from, and the rectangle's corners cut across the island's |
| 2026-08-27 | Error and warning banners (R17) are a **band tinted by the state token** (18 % over `surfaceRaised`), the icon in the token, the text in `textPrimary` | Colored text alone on the raised surface | Mockup `08` draws the banners as tinted bands and they read at once against the island; colored text alone was easy to miss in the first visual review |
| 2026-08-27 | `gutter` **6** instead of 8 (both sets); `islandRadius` stays 8 | Keeping 8 as read off the mockups | The author's eye on the running window after the first visual review: 8 pt of ground between the islands reads too loose next to the 36 pt bars |
| 2026-08-28 | **Fonts per area** (R6 amended; small = body − 2): interface = the system font at **13** (16 tried the same day, too large next to the code at 13) (`theme.interfaceFont` / `interfaceFontSize` to override, a fifth token family *Type*), code = **JetBrains Mono 13** (`terminal.font` / `fontSize`); every view goes through `ThemeService.font(_:weight:)` | SwiftUI text styles (`.callout`, `.caption`…) left in the views; one font for everything | The author chose the two fonts and sizes on 2026-08-28; the text styles scaled with macOS, not with Wraith's own size |
