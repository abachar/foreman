# M4 — Git

M4 = **seeing and committing your work**: the `git` feature (`Git/`), which calls the user's `git` binary in machine formats. Right panel `git.changes` (`cmd+shift+g`, moved from the left on 2026-08-27), bottom panel `git.history` (`cmd+shift+h`), center tab `git.diff`. By the end of M4, `cmd+shift+g` shows each repo of the workspace with its branch and its changes, a click opens the highlighted diff, `cmd+enter` commits with the user's hooks and signature, `cmd+shift+h` unrolls the log, and the explorer carries the status badges.

Domains covered: [`git`](../specs/git/); complements to `explorer` (R4 greying out gitignored entries, R15 badges) and `editor` (R18 gitignored entries in the quick open index), both deferred from M1 for lack of `Git.statusChanges`.

The **Library / native** column is mandatory (`AGENTS.md`). The **Tests** column: what is tested, nothing else — here, no test runs `git` and none touches the network (`coding-rules`: hermetic): what is covered is the parsers, the argument construction and the pure functions.

## Verified before M4 (2026-08-27, on the code of `main` 2bf4f0e)

The real APIs re-read on disk, not from memory. A file path for each one.

**Layout** (`Wraith/Layout/`):

- `PanelDescriptor(id:title:side:defaultShortcut:makeView:activate:deactivate:)` (`PanelManager.swift`): `makeView` is called **once** and the view is kept for the lifetime of the window (`PanelManager.view(for:)`); `activate()` / `deactivate()` bracket the panel's work (`git` R3, R4). `LayoutManager.register(panel:)` (`LayoutManager.swift:46`). `PanelID` is `ExpressibleByStringLiteral` (`"git.changes"`).
- `CenterTabDescriptor(kind:isTerminal:makeView:serialize:confirmClose:onClose:)` (`CenterTabDescriptor.swift`): `makeView: (TabID, String) -> AnyView?` — a payload that cannot be restored returns `nil` and the tab is ignored (`layout` R28).
- `LayoutManager.openTab(kind:title:payload:newGroup:isPreview:) -> TabID?` (`LayoutManager.swift:115`): `isPreview` already exists, so `git` R13's preview tab is free; `update(_:title:isDirty:isPreview:badge:)`, `activate(_:in:)`, `activateGroup(_:)`, `model.owner(of:)`, `register(tabKind:)`, `register(homeEntry:)`.
- `ShortcutRegistry.register(_ action: ShortcutAction)` (`ShortcutRegistry.swift`) **refuses an id that is already registered** (a `fault` log) and **has no unregistration**; `ShortcutScope = global | tab(kind:) | panel | terminal`; `ShortcutAction(id:title:scope:defaultShortcut:isLayout:perform:)`. The `panel` scope exists (`escape`, `layout` R22b): the message field's `cmd+enter` (`git` R10) is declared there, or stays native to the field — see "To decide".
- There is no shared "banner" component: `ExplorerPanelView` (`Wraith/Explorer/ExplorerPanelView.swift:19`) draws its own with a `Label` over `.background(.bar)`, and `WorkspaceView` does the same for `configError`. `Git/` does the same; there is nothing to extract for two callers.

**Workspace** (`Wraith/Workspace/`):

- `Workspace.configChanges() -> AsyncStream<WorkspaceConfig>` (`Workspace.swift:46`): **one stream per consumer** (an M3 fix); `Workspace.root`, `config`, `configError`, `state`, `fsWatch`, `setState(_:to:)` (a ~1 s debounced write).
- `WorkspaceConfig.section(_ name: String, as: T.Type) throws -> T?` (`WorkspaceConfig.swift`); `repos: [URL]` contains **existing folders only**: missing paths are already dropped at load time with a message in `config.warnings`. The spec's "repo declared but missing" edge case is therefore handled upstream; `Git/` only has to show `warnings`.
- `Workspace.persistedPath(for:root:)` / `url(forPersistedPath:root:)` (`Workspace+Paths.swift`) for the diff tab's payload (`config` R10).
- `Workspace.loginEnvironment() async -> [String: String]` (`Workspace+LoginEnvironment.swift`): `$SHELL -l -c '/usr/bin/env -0'`, resolved **once per window**, falling back to `ProcessInfo`. That is where `GitCLI` finds the user's `PATH` to resolve the `git` binary (R26).
- `FSWatchService.changes(under location: URL) -> AsyncStream<[URL]>` (`FSWatchService.swift:30`), prefix filtering, batches debounced at 300 ms. **The service is built over `roots: [root]`** (`Workspace.init`): it only sees what is under the workspace root. Since `config.repos` is resolved under the root, every repo is covered, `.git/` included.
- **`SecretStore` does not exist**: no file, no use of Security.framework in `Wraith/` (only the string "Keychain" appears, in the `password` warning in `WorkspaceConfig.swift:83`). M4 does not need one (R22: no secret enters Wraith); M5 creates it.

**Highlight** (`Wraith/Highlight/`):

- `Highlighter(theme:)` exposes two things (`Highlighter.swift`): `attach(to: NSTextView, language:) -> TextViewHighlighter?` for a live editor, and `highlight(_ code: String, language: Language) async -> AttributedString?` for static text (used by the markdown preview). **It is the second one the diff uses**: the diff is read-only, it does not need an incremental session.
- `Language` (`Language.swift`): 14 grammars wired, `Language.forFile(_ url: URL) -> Language?` (file name then extension), `lineCommentPrefix`. **`sql` is not wired** (removed in M1, coming back in M5): no effect on M4. An unknown extension → `nil` → a diff with `+`/`−` colors only (R13, the degradation is already provided for).
- `Highlighter` is created inside `EditorFeature` today (`EditorFeature.swift`), not in `App`: `Git/` needs an instance; anchoring it in `WorkspaceView` and injecting it into both features is one line — noted in task 4.6.

**Palette** (`Wraith/Palette/`): `Palette.present(_ source: PaletteSource, over: NSWindow)`, `PaletteSource(placeholder:results:select:secondary:)`, `PaletteItem(id:title:subtitle:)` + `PaletteItem.highlighted(_:matching:)`, `Palette.limit = 50`, keys handled by `PalettePanel.sendEvent` (`↑↓`, `enter`, `cmd+enter`, `opt+enter`, `escape`).

**Editor** (`Wraith/Editor/`):

- `EditorFeature.open(_ url: URL, preview: Bool, newGroup: Bool = false, line: Int? = nil)` (`EditorFeature.swift:371`): **it takes an absolute `URL`, not a path**. The `git` R7 spec writes `Editor.open(path)`: it is the file's `URL` that must be passed, not the relative string.
- `EditorFeature.fileRenamed(from:to:)`, `fileDeleted(_:)`, `path(of: TabID) -> String?`, `EditorFeature.tabKind = "editor.file"`.
- `QuickOpenIndex` (`QuickOpenIndex.swift`) is an `actor`: `init(root:)`, `build()`, `apply(_ changes: [URL])`, `search(_:limit:)`, `nonisolated static isSkipped(_:rootIsHome:)`. **It has no input for gitignored paths**: `editor` R18 requires adding an entry point (a method that receives the set of ignored paths) — an API to create, noted in task 4.10.

**Explorer** (`Wraith/Explorer/`):

- `ExplorerFeature.register(in:workspace:editor:)` is a `static func` on an `enum` that **returns nothing** (`ExplorerFeature.swift:9`): the model lives inside the `PanelDescriptor`'s closures. To wire up `Git.statusChanges` (explorer R15), it must return its `ExplorerModel` — **an API change to plan**, one line (task 4.10).
- `FileNode` (`FileNode.swift`) carries `relativePath`, `kind`, `isExcluded`, `isUnreadable`: **no git status field**. The cell colors are set in `ExplorerOutlineView.swift:316`. The status goes next to the node (a `[String: GitFileStatus]` table in `ExplorerModel`) rather than inside `FileNode`, whose identity is `NSOutlineView`'s key.

**SPM dependencies** (`Wraith.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`): 24 pinned packages, **no git dependency**. M4 adds none: `git` is a binary launched by `Process`, decision 2026-08-25. The `pbxproj` is not touched.

**Spec**: `git` R26 cited "`git.path` from the global config", removed by the config decision of 2026-08-26 → corrected in 4.1. `explorer` R4 pointed at "`git`, R14" (following the active tab) instead of R15 (badges) → corrected in 4.1.

## Definition of done (M4)

- `cmd+shift+g`: each repo of the workspace as a section, the branch, `↑n ↓m`, the changes grouped into Conflicts / Staged / Changes; the panel launches nothing while it is hidden; a `git commit` done in the terminal shows up in < 1 s.
- Stage, unstage, discard per file and per section; discard asks for confirmation, naming the number of files.
- A message + `cmd+enter`: the commit goes through the user's hooks and signature (no bypass on the command line); a hook failure → the output in the banner and the message kept; *Amend* prefills the message.
- Clicking a modified file → an inline highlighted diff as a preview, numbered hunks, *Stage hunk* / *Unstage hunk* / *Discard hunk*; a double click pins the tab; the worktree diff follows the file's changes.
- `cmd+shift+h`: the repo's `--first-parent` log, 200 commits per page, a subject/author filter; a click → the commit's diff; a menu with checkout, branch, cherry-pick, revert, reset soft/mixed; `reset --hard` and `push --force` **absent from the UI**.
- Fetch / pull / push from the header; one remote operation per repo; a push that would ask for interactive authentication gives the banner with the command to copy, never a terminal and never a typed-in secret.
- Branches (list, checkout, creation, rename, deletion, upstream) and stash (push, apply, pop, drop) without opening the terminal.
- The explorer colors the files by status and greys out gitignored entries; `cmd+p` no longer offers ignored files.
- `git` missing from the `PATH` → a single banner, the rest of the app untouched; a repo whose `status` exceeds 30 s → a banner offering to remove it from `config.repos`.
- `xcodebuild test` covers every "Tests" line; **no test runs `git`**; lint clean; **no SPM dependency added**, the `pbxproj` not modified.
- `docs/specs/git` up to date; `git`'s `questions.md` emptied (`--ignored` settled); `shortcuts.md`: git rows 🟢.

## To decide during M4 (decisions expected)

- 4.1: **`git` R26, resolving the binary** — proposal: the login shell's `PATH` (`Workspace.loginEnvironment()`, already resolved once per window for the agents), overridable by `git.path` in the `git` section of `.wraith/config.json`; the "global config" wording disappears from the rule. Consistent with the config decision of 2026-08-26.
- 4.2: **one `GitCLI` instance per repo or one per window** — proposal: one per repo (the spec says so: a repo's writes serialise against each other, two repos do not have to wait for one another); the binary's path and its version are resolved once per window and handed to each instance, not re-resolved per repo.
- 4.4: **rendering the changes panel** — proposal: a SwiftUI `List` with sections rather than an `NSOutlineView`: the hierarchy is fixed (repo → category → file), there is nothing lazy to load per level, and the explorer's `NSOutlineView` has no reason to be copied here. To be revisited if a repo with 5,000 modified files drags.
- 4.5: **the scope of `cmd+enter` (commit)** — proposal: the message field is a native component and `cmd+enter` is captured there as one of the field's keys (like the palette's `cmd+enter`), not declared to the `ShortcutRegistry`: `shortcuts.md` marks it `native`, as the current git row already does. Alternative: a `ShortcutAction` with the `panel` scope — rejected, it would fire from any focused panel.
- 4.6: **rendering the diff** — **settled (2026-08-27, `git/decisions.md`): one SwiftUI `Text` per hunk.** The initial proposal was: a non-editable `NSTextView` with a single `AttributedString` built per file (line numbers in an `NSRulerView` gutter like the editor, `Highlighter.highlight` per file). Alternative: a SwiftUI `List` with one row per diff line — simpler to write, but selection and multi-line copy become home-made. To be settled on a 5,000-line diff.
- 4.6: **a shared `Highlighter`** — proposal: create it in `WorkspaceView` (like `ThemeService` and `Palette`) and inject it into `EditorFeature` and into `Git/`; it is moving one line, and it matches `architecture.md` (shared services created once in `App`).
- 4.9: **the branch list** — **settled (2026-08-27): a search sheet of the feature.** The proposal was: a search sheet belonging to the feature rather than the shared `Palette`: the palette is a modal window centred on the screen, and a branch list belongs to the repo's section. To be confirmed in use; the palette stays available if that proves uncomfortable.
- 4.10: **ignored files** (`git/questions.md`) — **settled (2026-08-27): `--ignored=matching` on every `status`**, measured on the author's repo at 16 ms with or without it (`--ignored` alone: 60 ms). The initial plan was to measure before choosing: `status --ignored=matching` in a single pass (the cost on a large repo) or `check-ignore -z --stdin` for the expanded folders only. Default proposal: `check-ignore` on demand, because it follows the explorer's laziness (R7: nothing is read before expansion); to be reversed if the measurement shows that `--ignored` is free.
- 4.4: **a repo deleted during the session** — proposal: the section stays, greyed out with the reason, until the next config reload, like a tab whose cwd is gone (`terminal` R16); no silent removal.
