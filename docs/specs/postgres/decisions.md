# postgres — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-27 | R9: `postgres.query` is a **center tab** (`cmd+shift+q` = a new `Query N` tab, several at once), not the bottom panel | The bottom panel (2026-08-25) | Author's choice: more room, several queries side by side, the bottom slot stays with the search; same model as `git.diff` |
| 2026-08-27 | R18: CSV/JSON export deferred out of v1 (noted as a future evolution) | Shipping it in 5.7 | Author's choice: not needed today; `cmd+c` as TSV covers the small cases |
| 2026-08-27 | R1, R3: an optional plaintext `password` in the `postgres` section, taking precedence over the Keychain chain; a refused config password is shown, not invalidated or re-asked | Keychain only (2026-08-25) | Author's choice for local dev databases (`config` decision 2026-08-27); the chain is unchanged when the key is absent |
| 2026-08-27 | R1, R12: a single config source, the workspace's `.wraith/config.json` (`postgres` section, `statementTimeout` included); the global/workspace merge disappears from the spec and from the tests | Keeping the global/workspace precedence wording | The config decision of 2026-08-26 removed the global file; a rule citing it would describe a merge that no longer exists |
| 2026-08-27 | `postgres.schema` defaults to **`cmd+shift+b`**; `cmd+shift+d` stays `layout.split.horizontal` | `cmd+shift+p`; keeping `cmd+shift+d` | A feature cannot take a layout shortcut (`layout` R24, checked in `ShortcutRegistry.rebuild`: `reservedByLayout`, the action is not bound); `b` reads as *base*, sits next to `cmd+shift+q`, and is free both in `shortcuts.md` and under macOS; `cmd+shift+p` stays free, it is the command palette elsewhere |
| 2026-08-27 | R10, R17: **one statement per execution** (the extended protocol); several statements → the server error `42601`, explained by a banner | `simpleQuery` (the simple protocol); a client-side SQL tokenizer | PostgresNIO does not expose the simple protocol: `PostgresDatabase.simpleQuery` falls back to `query(_:onRow:)`, hence to `PostgresQuery(unsafeSQL:)` and the extended protocol (read on 1.33.1); a home-made tokenizer is already rejected (2026-08-26, `architecture.md` P2) |
| 2026-08-27 | R12, R13: really stopping a query goes through `pg_cancel_backend(<pid>)` over a second connection, on top of `Task.cancel` | `Task.cancel` alone; reaching into PostgresNIO's `internal` encoder | `ExtendedQueryStateMachine.cancel()` moves the stream to `.drain`: the rows are discarded client-side, the server keeps going. `PostgresFrontendMessageEncoder.cancel(processID:secretKey:)` exists but is `internal`; `pg_cancel_backend` is ordinary SQL |
| 2026-08-27 | R1 `options` go to `PostgresConnection.Configuration.Options.additionalStartupParameters`; R11/R12 session settings go through `set_config($1, $2, false)` binds | `SET` statements with the value in the SQL text | The startup parameters are what `libpq`'s `options` are; `SET` takes no bind parameter, `set_config` does (R15: values are bound, never interpolated) |
| 2026-08-27 | R6: column types are formatted by the server (`format_type(atttypid, atttypmod)`), defaults by `pg_get_expr`, indexes/constraints/views/functions by `pg_get_*def`; no client-side type formatter | A client `TypeFormatter` over `typname` + `typmod` | `architecture` P2/P3: the server already does it exactly (arrays, domains, extension types); the only client-side reconstruction is the table DDL, which the server has no function for |
| 2026-08-27 | R8: *View the DDL* is best effort, headed by "Reconstructed by Wraith from pg_catalog, not the server's definition"; tables only are rebuilt, views/functions/indexes wrap the server's definition; no composite types, no RLS policies | Full `pg_dump`-like output | The need is reading, not migrating; `pg_dump` is one command away |
| 2026-08-27 | R6: the tree's root is the database row; `activate()` loads nothing, expanding the root runs the first query | Loading the schemas on activation | R4: the connection waits for the first action; the root row makes that action visible |
| 2026-08-27 | One `PostgresConnection` per window, not the library's `PostgresClient` pool | The `PostgresClient` pool | The pool needs a live `run()` task and brings nothing to a single consumer (R4: one connection per window) |
| 2026-08-26 | **One connection per workspace** (`config.postgres` = one object), no picker (replaces "named profiles" of 2026-08-25) | Named profiles with a picker | Product vision: one workspace = one database; less UI, a single Keychain key; changing database = editing the config |
| 2026-08-25 | Password: Keychain → `~/.pgpass` (0600) → typed in, with a save to the Keychain | Typing it every time; `password` in the config | `config` R11; `.pgpass` is the user's existing convention |
| 2026-08-25 | The full schema level by level from `pg_catalog` (schemas, tables, views, mat views, functions, sequences, types; columns, indexes, constraints, FKs) | Tables/columns only; `information_schema` | The real need is to explore an unknown database; `pg_catalog` is fast and complete |
| 2026-08-25 | A read-only grid, autocommit, a `default_transaction_read_only = on` session with a non-persisted write toggle | Editing in the grid; transactions in the UI | An exploration tool; an accidental write is the real risk, a deliberate write stays possible |
| 2026-08-26 | Bounds: `LIMIT 500` on SQL generated by Wraith; free-form SQL read as a stream, cut off at 50,000 rows by cancelling the task, with a warning; `statement_timeout` 30 s (replaces "pages through a portal" of 2026-08-25) | Portal + `Execute(maxRows)`; a `LIMIT` injected into the user's SQL; loading everything | Use PostgresNIO the way it is designed (streaming) rather than driving the extended protocol by hand; the user's SQL is never rewritten |
| 2026-08-25 | CSV/JSON export of the loaded result or re-streamed (capped at 1M rows) | No export | A frequent need, a low cost |
| 2026-08-25 | Query history in `.wraith/postgres-history.json` (500, FIFO, pinning), never versioned | No history; inside `state.json` | A dedicated file so `state.json` does not grow; the `.gitignore` rule matches |
| 2026-08-26 | The SQL editor = a monospaced text area of the feature's own, colored through the shared `Highlight/` folder (replaces "no highlighting" of 2026-08-25) | Reusing `editor`'s editor tab | The editor tab is a center tab, not a panel component; highlighting is a shared component (`architecture.md`) |
| 2026-08-26 | Execution: the selection, otherwise **the whole buffer** in one `simpleQuery`; Postgres splits the statements (replaces "the statement under the cursor" of 2026-08-25) | The statement under the cursor with a client-side SQL tokenizer (`'…'`, `$$…$$`, comments) | No home-made tokenizer (`architecture.md` P2); selecting what you want to run covers the need |
| 2026-08-26 | `PostgresClient` a concrete type, no `DatabaseService` protocol and no `FakeDatabaseService` | A protocol + a test double | A single implementation (`architecture.md` P1); the panels are tested over hand-built `QueryResult` values |
