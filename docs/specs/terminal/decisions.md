# terminal — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-26 | **SwiftTerm alone**; libghostty dropped (replaces "libghostty embedded" of 2026-08-25) | libghostty as the main path + SwiftTerm as a fallback; SwiftTerm as the main path + libghostty optional | The need is to show agent TUIs and build output, not to be a terminal emulator; SwiftTerm is enough, with no zig build and no vendored C |
| 2026-08-26 (afternoon) | **PTY and process through SwiftTerm's `LocalProcessTerminalView`**, used as designed; the exit code through `processTerminated`, the pid exposed for signals (replaces "a home-made `PTYSession`, `forkpty`" of 2026-08-26 morning) | A home-made PTY + `forkpty` + `waitpid`, SwiftTerm as pure VT | `architecture.md`: we do not write what a library already does; SwiftTerm provides the pid, the exit code and resizing |
| 2026-08-26 | One tab = **one process** launched through `$SHELL -l -c "<command>"`, with no prompt; process ended → a frozen surface + *Relaunch* | An interactive shell into which we `send()` the command; auto-close at the end | No free-form shell (`product` R4); the login shell's environment is preserved; the output stays readable after the end |
| 2026-08-26 | State from the end of the process (SwiftTerm), cwd = the launch cwd, **no shell integration** OSC 7/133 | Injecting shell integration | Reliable whatever the shell; nothing left to inject |
| 2026-08-26 | A fixed title provided by the feature; OSC 0/2 as a subtitle only | A dynamic title | The tabs are `Claude`, `backend:test`… identity wins |
| 2026-08-26 | Appearance (font, theme) handled by Foreman through `ThemeService` + the global config | The user's Ghostty config | No more Ghostty; a single theme for the whole UI |
| 2026-08-27 | The appearance override (R14) comes from the `terminal` section of `.foreman/config.json`, not from a global config | `~/.config/foreman/config.json` | Follows the config decision of 2026-08-26: a single source, per workspace |
| 2026-08-27 | **SwiftTerm `v1.20.0`**, `.upToNextMinor` | The `main` branch | The API we use is identical (`startProcess(...currentDirectory:)`, `processDelegate`, `bell`, `clearScrollback`, `installColors`); `main` rewrites `LocalProcess` with no gain for us; `architecture.md`: `.upToNextMinor` versions |
| 2026-08-25 | `cmd+w` asks for confirmation while the process is running; `SIGKILL` only on a forced close after 5 s | A direct kill; never a confirmation | Avoids killing a server or an agent by mistake |
| 2026-08-25 | Foreman's `cmd+…` shortcuts take priority over the surface | The surface wins | Tabs and splits are Foreman's |
| 2026-08-27 | Confirmed in use (M6 6.4): `bellStyle = .none` and R7's badge on an inactive tab, no visual bell | Going back to `.visual` | The badge is what the eye needs; a flashing surface under an agent is noise |
| 2026-08-27 | Confirmed in use (M6 6.2): `cmd+c` copies the selection, `ctrl+c` reaches the process; no agent needed `cmd+c` | Passing `cmd+c` to the process when there is no selection | No agent among the four used depends on it; one rule is easier to remember |
| 2026-08-28 | Default monospaced font: **JetBrains Mono 13** (the system monospaced font when absent) | The system monospaced font | The author's choice for the editor, the terminal, the diff and SQL (design R6) |
| 2026-08-30 | R7 also asks for the user's attention (`requestUserAttention(.criticalRequest)`, the Dock bounces until Foreman is activated) when the bell rings or a process ends while the app is in the background | A notification centre banner (`UNUserNotificationCenter`); `.informationalRequest` (one bounce); a numbered Dock badge | Nothing to authorize, nothing to sign, ten lines; a single bounce is missed if the user is not looking, while the request stops by itself on activation. Foreman cannot tell "waiting for input" from "finished": both are a bell, so the wording stays honest. The badge counts across windows, which nothing owns today (deferred) |
| 2026-08-30 | Writing to a tab that holds no process is an error (`noProcess`), not a silent no-op (R16) | Returning without writing, as before | A mention sent to a restored agent tab vanished with no trace anywhere; the caller now shows the tab, whose Relaunch bar is the answer (audit T8) |
| 2026-08-30 | The zoom of a surface is kept on the surface and re-applied with the theme's font (R14) | Setting the font directly, as before | Every `apply` reinstalls the theme's font, so a config reload or an appearance change silently undid `cmd+=` (audit T1) |
| 2026-09-09 | `shift+enter` is sent to the process as `ESC CR` (R12, issue #4) | Leaving SwiftTerm's bare `CR`; a per-agent option; remapping only the agent surfaces | A bare `CR` submits in Claude Code, so multi-line prompts were impossible; `ESC CR` is the sequence its `/terminal-setup` binds in iTerm/VS Code for exactly this. One rule for every surface (like `cmd+c`, decision 2026-08-27): the run surfaces barely read the keyboard, and no hosted process distinguishes usefully a bare `CR` from `ESC CR` typed by hand |
| 2026-10-16 | `TerminalService.start` launches a session without a center tab, for the Run panel's sub-tabs (R16, M21 21.5) | A second service for panel terminals | The surface, the process and the states are the same; only where the view is placed changes |
| 2026-10-17 | The main thread's cost under two streaming agents is the CoreGraphics draw, not the VT parser: `TerminalView.draw` carries 55 % of the main-thread samples (one `NSAttributedString` per row per frame, the box-drawing renderer), AppKit's own cycle 37 %, `Terminal.feed` 2.5 % (R14; audit 2026-10-17 U1; M23 23.1). 23.6 is re-scoped from « the parser off the main thread » to SwiftTerm's Metal renderer, on the author's decision | Handing `LocalProcess` a serial queue per surface (the audit's U1) | A 120 s trace on `ccoe`, Release build, the author at the keyboard: moving 2.5 % off the main thread would change nothing visible; the library documents `setUseMetal(_:)` for exactly this cost |
| 2026-10-17 | Every surface draws through SwiftTerm's Metal renderer (`setUseMetal(true)` when the view enters its window), with the library's default buffering mode (`.perRowPersistent`); CoreGraphics is kept when `setUseMetal` throws (R14; audit 2026-10-17 U1; M23 23.6) | Keeping CoreGraphics; moving the VT parser off the main thread (the audit's U1); a `terminal.renderer` config key | Under two streaming agents on `ccoe` the CoreGraphics draw held 55 % of the main-thread samples, AppKit's cycle it drives another 37 %, the parser 2.5 %, with 1,007 update cycles over the 8.33 ms frame: the parser is not the cost. The author chose Metal on 2026-10-17. The library recovers from stalled frames and falls back to CoreGraphics by itself (`metalRendererStatus`), so a key would only duplicate that fallback |
