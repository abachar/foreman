- [ ] **A non-interactive login shell does not read `.zshrc`** (found 2026-08-31, on a React project; `terminal` R3, `agents` R2, `editor` R35/R46, `run` R2): `loginEnvironment()` runs `$SHELL -l -c`, which sources `.zshenv`, `.zprofile` and `.zlogin` but **not** `.zshrc` — that one is for interactive shells. Anything the user exports there is invisible to everything Foreman launches. It surfaced through LSP because `typescript-language-server` is a `#!/usr/bin/env node` script and Homebrew's `node@24` is keg-only: `/opt/homebrew/bin` comes from `.zprofile` so the binary was found, `/opt/homebrew/opt/node@24/bin` comes from `.zshrc` so `node` was not, and the server died with `env: node: No such file or directory`. Formatters, agents and `run` commands hit the same wall for any node-based tool. Three ways out, none obviously right: leave it and let the user move the export to `.zprofile` (what was done on this machine, and what most GUI editors expect); resolve the environment with `-l -i` as VS Code does, which sources `.zshrc` but also runs prompts, completions and anything else an interactive session starts; or keep `-l` and say plainly, once, that the environment comes from the login shell. R39's banner already quotes the failure, which is how this was found at all — the question is whether Foreman should also prevent it.
