# explorer — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-25 | Dotfiles visible; gitignored entries and folders on the exclusion list greyed out; `.git/` hidden; a toggle to hide the greyed-out ones | Dotfiles hidden (Finder); everything visible without greying | We often work in `.github`, `.env.example`…; greying gives the information without hiding it |
| 2026-08-25 | Basic CRUD (create, rename, delete to the trash, reveal, copy path), no drag and drop ("terminal here" removed on 2026-08-26, `product` R4) | Read-only; CRUD + D&D | The daily need without the cost of D&D; moving is done by the agent or outside Foreman |
| 2026-08-25 | Single click = preview tab (replaced), double click or an edit = pinned tab | Single click = pinned tab | The VS Code model, avoids piling up tabs |
| 2026-08-25 | The tree follows the active tab (a persisted toggle) and shows the git badges received from `Git.statusChanges` | An independent tree; an explorer that reads git itself | A single source of git status; the explorer never runs `git` |
| 2026-08-25 | Loading level by level, targeted reload of the parent folder on FSEvents, never a recursive walk | A full in-memory index of the workspace | Laziness (`architecture.md` P4); a `$HOME` workspace is possible |
| 2026-08-25 | Delete to the trash with confirmation, never a permanent delete | A direct `rm -rf` | Reversible; the terminal is there for the permanent kind |
| 2026-08-26 | View = `NSOutlineView` with a lazy data source; reloading through `reloadItem(_:reloadChildren:)`, no hand-written tree merge | SwiftUI `List`/`OutlineGroup`; a hand-merged tree model | Platform first (`architecture.md` P3): performance on large folders, state preservation for free |
| 2026-08-27 | New file / folder: the name typed in a sheet (`NSAlert` + a field); renaming stays inline in the cell | A ghost editable row in the `NSOutlineView` | A ghost row needs a fake item in the data source and its synchronisation; the sheet does the job in 20 lines |
| 2026-08-28 | Rename on a double click (or `enter`, or the menu); the cell's label is editable only while a rename runs | The label always editable (AppKit then starts editing on a single click on a selected row, taken for a bug in use); the double click kept for pinning (R12) | Asked in use: the accidental rename on a click was the annoyance; pinning still has `cmd+↓`, `cmd+k` and the first edit |
| 2026-08-28 | **IntelliJ opening**: a click selects, a double click or `enter` opens pinned, no preview from the tree; rename from the menu or `shift+F6` | The morning's fix (double click = rename); the original preview-on-click | The double click for rename clashed with "double click opens" every editor teaches; the preview replaced tabs the author wanted kept |
| 2026-08-28 | Drag and drop moves inside the tree (R22), no confirmation, a clash refuses | Copy on `opt`; accepting Finder drops; a confirmation sheet | Asked in use; a move is reversible by dragging back, a clash must not overwrite |
| 2026-08-30 | Folders with a single child are folded into one row (`src/main/java`, `explorer` R23), the chain resolved **at expansion** only; rename and drop target the last segment; no config key | IntelliJ's read-ahead (the chain shown on a collapsed tree); a `explorer.compactFolders` key | The read-ahead would list folders the user never opened, against P4; the visible cost is that a collapsed row still reads `src`. A key would cost a config entry, a line of `docs/config.md` and a second code path for a setting chosen once |
| 2026-08-30 (implementation) | A folded row is persisted under its own path (`src`), not under the last segment of its chain (R11, R23) | Persisting `src/main/java` as R11 first said | Restoring has to reopen the row `src`, and nothing says `src/main/java` is still its chain before the folder is read; a "a prefix is enough" rule would also reopen folders the user closed on purpose |
| 2026-08-30 | `.foreman/scratches/` hidden from the tree (R3), like `state.json` | Showing it greyed out (R4); a `.foremanignore`-style list | A draft has no name the user chose and no place in the workspace; greying it out would still put `Untitled` under the user's eyes at every level of the tree |
| 2026-08-30 | The root check resolves symlinks on both sides (R19) | Standardising the path only, as before | `standardizedFileURL` resolves `..` and nothing else, so a link inside the workspace pointing outside passed the check and rename, delete and create all followed it out. The root is resolved too, being often a link itself (audit T7) |
| 2026-08-30 | A case-only rename moves the file back when the second move fails (R17) | Leaving the two moves unguarded | On a case-sensitive volume the target can already exist: the file was then stranded under an invisible `.x.foreman-rename` name with nothing to bring it back (audit M12) |
