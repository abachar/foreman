- [ ] **Two servers for one extension** (2026-08-31, [03-study-lsp.md](03-study-lsp.md) R35, edge cases): an Angular project wants `typescript-language-server` *and* `ngserver` on the same `.ts` — the first for TypeScript, the second for the Angular semantics of inline templates — which is what every editor with real Angular support runs. R35 maps one extension to one command, so v1 declares `typescript-language-server` on `.ts`/`.tsx`/`.js` and `ngserver` on `.html`: the templates keep their diagnostics, only the Angular part of the *inline* ones is lost. Accepting an array of commands per extension is backwards compatible (a string stays valid) but forces a policy — diagnostics concatenated from every server, and one owner to pick for hover and go-to-definition. To settle from use on a real Angular project, not before.
