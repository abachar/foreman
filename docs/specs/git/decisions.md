# git — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-25 | The `git` binary through `Process`, machine formats (`--porcelain=v2 -z`, `--format`) | libgit2 / SwiftGit2 | Hooks, signing, credential helpers, `pull.rebase`… honoured for free; no C to wrap; SwiftGit2 is barely maintained |
| 2026-08-25 | Full scope: status, stage/unstage/discard, commit/amend, per-hunk diff, log, fetch/pull/push, branches, stash | Read-only; stage+commit only | The terminal stays available, but the daily work fits in the panel |
| 2026-08-25 | Every repo stacked as collapsible sections | One repo at a time | An overview of a multi-repo workspace (the main use case) |
| 2026-08-25 | An inline unified diff in a center tab; a linear `--first-parent` log in a bottom panel | Side by side; a branch graph | Enough to review before committing; the graph is a large rendering project |
| 2026-08-26 | The diff colored through the shared `Highlight/` folder (replaces the "no highlighting" decision of 2026-08-25) | tree-sitter imported into `Git/`; +/− diff only | Highlighting is a shared component (`architecture.md`); `Git/` calls it directly |
| 2026-08-26 | `GIT_TERMINAL_PROMPT=0`; an interaction required → a banner with the command to copy, no terminal opened (replaces "switch to a terminal" of 2026-08-25) | Typing credentials into Foreman; an ephemeral terminal surface | No secret in the app (`architecture.md`, security); no free-form shell (`product` R4); the case is rare with a configured helper/SSH agent |
| 2026-08-25 | Discard, drop stash, `-D`, checking out a commit, reset, cherry-pick, revert: confirmed; `reset --hard` and `push --force` absent from the UI | Everything reachable; nothing destructive | The destructive stays explicit; the irreversible stays in the terminal |
| 2026-08-25 | Never an automatic `fetch`; refreshing through FSEvents (worktree + `.git/HEAD`, `index`, `refs/`) | Polling; a periodic fetch | No unrequested network, no disk polling (`architecture.md`) |
| 2026-08-26 | `GitCLI` a concrete type, no `GitService` protocol and no `FakeGitService` | A protocol + a test double | A single implementation (`architecture.md` P1); the parsers are tested over fixtures, the panel over hand-built `GitStatus` values |
| 2026-08-25 | Commit through `-F <temporary file>`, without `--no-verify` and without bypassing the config | The message as an argument; a "skip hooks" option | Safe multi-line messages; the user's hooks are their policy, not ours |
| 2026-08-27 | The `git` binary resolved once per window in the login shell's `PATH` (`Workspace.loginEnvironment()`), overridable by `git.path` in the `git` section of `.foreman/config.json` | A global config key; `/usr/bin/git` hard-coded | The global config was removed on 2026-08-26 (`config`); the login `PATH` is what the agents already use, so the user's Homebrew git wins over Apple's as in their terminal |
| 2026-08-27 | One `GitCLI` instance per repo; the binary's path and version resolved once per window and handed to every instance | One instance per window | A repo's writes serialise against each other, two repos never wait for one another; resolving the binary per repo would repeat the same work |
| 2026-08-27 | The changes panel is a SwiftUI `List` with sections, not an `NSOutlineView` | Copying the explorer's outline view | The hierarchy is fixed (repo → category → file) with nothing lazy to load per level; to be revisited if a repo with thousands of modified files drags |
| 2026-08-27 | `cmd+enter` (commit) is a key of the message field, not a `ShortcutAction` | A `panel`-scoped `ShortcutAction` | A panel-scoped action would fire from any focused panel; the field is native and captures it like the palette does (`shortcuts.md`: `native`) |
| 2026-08-27 | `git.changes` lives in the **right** slot | The left slot, as specified on 2026-08-25 | Seen in use: the author wants the explorer and the changes side by side; the left slot is the explorer's. The right slot is shared with `postgres.schema` (M5), one visible at a time (`layout` R2) |
| 2026-08-27 | The diff is rendered as one SwiftUI `Text` per hunk (an `AttributedString` with the highlighting and the `+`/`−` tint, two gutter texts beside it), inside a scroll view of files | A single non-editable `NSTextView` for the whole diff; a `List` with one row per line | R15 puts buttons on every hunk header and R16 collapses per file: a SwiftUI layout gives both for free, and `Text` keeps native selection and copy within a hunk. To be revisited on a 5,000-line diff |
| 2026-08-27 | One `Highlighter` per window, created in `WorkspaceView` and injected into the editor and `Git/` | A second instance inside `Git/` | `architecture.md`: shared services created once; the parsed grammars are shared |
| 2026-08-27 | The diff is **side by side by default**, inline on demand (R13b); the per-hunk stage/unstage/discard of R15 is **removed** | Inline only (2026-08-25); R15 | The author reads a side-by-side diff faster and does not stage by hunk; the pairing is a pure function over the parsed hunk, nothing else changes |
| 2026-08-27 | The branch list is a **sheet of the feature** with a search field, not the shared `Palette` | The `Palette` | The palette is a modal window centred on the screen; the branch list belongs to the repo's section and carries per-branch actions (rename, delete, upstream) the palette has no room for |
| 2026-08-27 | Ignored entries come with every `status`, through `--ignored=matching` | `check-ignore -z --stdin` on the expanded folders; a full `--ignored` | Measured on the author's repo: 16 ms with or without `--ignored=matching`, 60 ms with `--ignored`; one command, no second mechanism, and the quick open index gets the same table |
| 2026-08-27 | `git.history` shares the **right** slot with `git.changes`: showing one hides the other | The bottom slot (2026-08-25) | Seen in use: the author wants the history where the changes are, not under the editor; `layout` R2 gives the swap for free |

| 2026-08-28 | Session diff base = a tree written from a temporary index (`GIT_INDEX_FILE` + `add -A` + `write-tree`), diffed against a tree rebuilt the same way (`01-study-session-diff.md`) | `git stash create` (no untracked files, touches nothing either); diffing `HEAD` at spawn; copying the worktree | Untracked files are what an agent creates most; the real index is never touched (R29); a commit-less object is enough for `git diff` |
| 2026-08-29 | No repo → no git panels, toggles or shortcuts (R1b, `layout` R36) | An empty Changes panel with "No Repository" | The panel had nothing to offer and its two shortcuts still occupied the home screen; the `ContentUnavailableView` stays for the window where the last repo disappears |
| 2026-08-30 | The Changes panel renders each group (Conflicts, Staged, Changes) as a **tree**, folders with a single child folded into one row; folder rows carry no action | Keeping the flat list; one tree for the whole repo; a list/tree toggle | Use: a repo whose changes span several folders was unreadable flat. Per-group trees keep the existing group actions and the existing row; a toggle would add a setting and a persisted state for a case that solves itself (three files read as three rows) |
| 2026-08-30 (implementation) | The file row's grey line drops the parent folder and keeps only a rename's origin (R6b) | Leaving the parent on the row as R6b first said | The folder rows above the file already spell the parent out; printing `src/main/java` again under `Foo.java` is the flat list the tree replaces |
| 2026-08-30 | A merge commit's diff (R14, R19) is what it brought to its first parent (`show -m --first-parent`) | The combined `diff --cc` git shows by default; "no diff for a merge" | The combined format is not a unified diff: the parser read it as nothing and the tab said "No Changes". Against the first parent, the tab shows what merging added to the branch, which is what the history panel is read for |
| 2026-08-30 (from use) | A folder row of the Changes tree **closes and opens** on a click; the fold lives in the view, not in `state.json` (R6b) | A fixed tree, as R6b first said; persisting the fold in `state.json` | Read as fixed, the tree gives no way to put a noisy folder aside. Persisting it would outlive the changes it was hiding, which are gone by the next commit |
| 2026-08-30 | The two ref formats are spelled differently on purpose (R27): `for-each-ref` expands `%1f` itself, `stash list` goes through the pretty machinery where only `%x1f` is an escape and `%1f` is printed literally | One spelling for both | Verified against git 2.54: with `%1f` the stash list never found its separator and the panel's stash section was permanently empty (audit C3) |
| 2026-08-30 | The history's `--grep`/`--author` filters are passed with `--fixed-strings`, and an unfiltered page keeps git's own order (R20) | Passing the user's text as a regex; re-sorting by author date | A `(` typed in the filter made git error out, and re-sorting sank a rebased commit far below `HEAD` (audit G5, M10) |
| 2026-09-09 | A repo is excluded from tracking through a `!` entry in `config.repos` (`"!vendor/lib"`, `"!."` for the root), applied to the declared list and to the scan alike (R1, issue #5) | A separate `git.ignore` key; a boolean per repo | `repos` already owns which repos exist, so the exclusion belongs there; one key, no merge rule to add (arrays are replaced whole), and `agents`/`run` — which read the declared list — never see an exclusion |
| 2026-10-16 | A repo's worktrees are **child sections** of it in the Changes panel, whoever created them (`02-study-worktrees.md` R33–R34) | A `worktree` badge in the branch list only; a separate Worktrees panel | The author wants to read an agent's uncommitted work from the main window; only a section shows the changes, and a section is what the panel already knows how to draw |
| 2026-10-16 | *Check Out Here* = `git worktree remove` without `--force`, then `git checkout` in the parent (R37) | `git checkout --ignore-other-worktrees`; removing with `--force` | Two folders on the same branch drift apart at the first commit; without `--force` git itself refuses a worktree holding uncommitted work, so the action never loses anything |
| 2026-10-16 | A repo with worktrees is a **group**: its main working copy is its first child section, beside the worktrees; each child is headed by its branch, the folder in grey (`02-study-worktrees.md` R34, R34b) | The parent section holding its own changes with the worktrees under them; folding the parent hiding only its own changes; the folder name as the title | Folding the parent hid the worktrees with it, and a chevron that hides only part of what lies under it surprises; a worktree holds one branch and a branch one worktree, so the branch is the unique, meaningful title |
| 2026-10-16 | *Compare with <base>* on a worktree child: the history narrowed to `<base>..<head>` and one diff tab of `<base>...<head>` (`02-study-worktrees.md` R36b) | The history panel's plain log of the child (R34a) only; a two-dot diff | The plain log mixes the agent's commits with the whole history of `main`; three dots show what a merge would bring and ignore what `main` gained since the fork |
| 2026-10-16 | Each working copy carries a badge per agent session whose cwd lies in it, state included, a click activating the tab; sessions first, re-sorted only when a session opens or closes (`02-study-worktrees.md` R34c) | No link between sections and agents; re-sorting on every state change | The aim is to see what each agent does from one window; the section shows the work, the badge says who does it and whether it still runs; rows that jump while agents work cannot be clicked |
| 2026-10-16 | Selecting a commit in the history lists its files as a tree under the log; a file's click previews its diff in the center; the whole commit's diff moves to the double click (R19, R19b) | Opening the whole commit's diff on a click (R19 as it was); the files in a popover | Reading a commit file by file is what the author does; the tree is R6b's, already familiar from the Changes panel |
| 2026-10-16 | The diff tab is side by side only (R13b amended) | Keeping the inline layout behind its control | The author never uses inline; one layout is less code and one less control on every diff |
| 2026-10-16 | One commit area at the bottom of the Changes panel, its target picked among the working copies and following the last one worked in (R10 amended) | A message area at the end of each section | With several repos and worktrees, each section's area was far down the list, often off screen; the author wants it always in reach |
| 2026-10-16 | The explorer, the Changes panel and the history's commit files share one tree (`Layout/FileTree.swift`): the outline's setup, its row, a read-only tree; the explorer keeps its own data source (lazy levels, rename, drag and drop) on top | A SwiftUI tree imitating the explorer; one generic explorer with extension points | The three trees looked different; sharing the setup and the cell makes drifting impossible, and the explorer's own features need no hook a second caller would not use |
| 2026-10-16 | Changes is a tab of the left slot, History a tab of the bottom slot (surfaces amended, M21 21.1) | Both in the right slot (2026-08-27) | Reference views 04–05: changes beside the project tree they belong to, the log across the centre's width; the right slot is left to the Database |
| 2026-10-16 | History stays the **linear log** of R18, with its branch and tag chips; branch lanes wait for a later milestone (M21, to decide for 21.6) | Drawing the lanes of view 05 now | Author's call: the lanes need a graph layout of their own; the chips already say where the branches are |
| 2026-10-16 | The status is followed while the window has a repo, whatever panel is shown (surfaces amended, M21 21.2) | Following it only while *Changes* is shown (P4) | With History in its own slot it showed *No Repository* until Changes was opened once; the Changes count and the branch widget need it too |
| 2026-10-16 | A branch menu on the toolbar's branch widget, with a filter field, worktrees, local and remote branches and the remote actions (R40, M21 21.4) | The branch sheet of the Changes panel only | Reference view 11: switching, comparing or pulling is one click from anywhere; the actions are the existing ones (R21–R24, R36–R38), only the way in is new. The filter is an `NSSearchField` in an `NSMenuItem`, so the menu stays native |
| 2026-10-16 | History in the bottom slot reads in columns with ref chips, the commit's details and files beside the log, and a Current / All branches choice (R18, R19b amended, M21 21.6) | Keeping the side-panel layout (files under the log) at full width | View 05: at the centre's width a split under the log wasted the line; beside it, the log keeps its rows and the files their tree |
| 2026-10-17 | *New worktree…*, *Open <agent> here* and *Merge into <base>…* in the branch menu (R41, M22 22.2) | Keeping the worktree actions in the Changes panel's header only | Author's pass on M21 (view 11): the worktree flow — create, hand to an agent, merge back — from one menu; the worktree folder beside the repo is the layout of view 04 |
| 2026-10-17 | History's actions in a row under the tabs (R18 amended) | In the tab header (M21 21.6) | Author: the same layout as Search and Problems; the header keeps the tabs alone |
| 2026-10-17 | R16 — a large diff renders its expanded files first and publishes each file as it is rendered; a folded file is rendered when it is unfolded, not before; a refresh keeps the hunks of the files that did not change (audit 2026-10-17 M2, M23 23.2) | Rendering every file and publishing the whole diff once (one publication, no flicker) | On the author's workspace a session diff reaches 228 files / 22,000 lines: nothing showed until everything was rendered, and the folded files were built and kept although they may never be opened. A worktree or session diff refreshes on every status while an agent writes (R17): re-rendering every file would blank the hunks at each refresh |
| 2026-10-17 | A repo and an agent session carry their canonical path; `GitModel` compares strings, no `realpath` in a body; a section's three lists are built once per status (audit 2026-10-17 U5, M23 23.3) | Resolving the symlinks and splitting the status on every read | `groups` and `agentSessions(in:)` run in the body of the Changes panel: one `realpath(2)` per repo and per session at each evaluation |
| 2026-10-17 | After 23.2, a refresh with no changed file re-renders nothing (`diff.render` 0.04 ms measured); scrolling a large rendered diff still gives 8–15 ms frames in `GitDiffView.hunkView`, one `HStack` per line — a study before any change (R13, R16; audit 2026-10-17 M2; M23 23.1 → 23.9) | Rewriting the hunk view at once | The trace names the cost but not the fix: `LazyVStack` already bounds the rows, so the next lever (one `Text` per hunk, or an `NSTextView` per file) is weighed in the study |
| 2026-10-17 | Study of the large diff's scrolling (M23 23.9): the first lever is one flat `LazyVStack` whose direct children are the file headers, the hunk headers and the rows — today the rows sit in a `LazyVStack` nested in a `VStack` in the tab's `LazyVStack`, and a nested lazy stack is not lazy: every row of every expanded hunk is built as soon as the hunk is.
