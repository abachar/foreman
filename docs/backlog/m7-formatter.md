# M7 — Formatage

M7 = **rendre le fichier propre sans quitter l'onglet** : `cmd+shift+l` formate le fichier actif avec le formateur que l'utilisateur a déclaré pour cette extension, et `formatter.onSave` le fait à la sauvegarde. Extension du domaine `editor`, **pas un nouveau domaine** : pas de dossier `Formatter/`, pas de feature, pas de panneau — le code vit dans `Wraith/Editor/`.

Domaine couvert : [`editor`](../specs/editor/), étude [`01-study-formatter.md`](../specs/editor/01-study-formatter.md) (règles R24–R33, numérotation continuée depuis `00-study.md`).

Colonne **Lib / natif** obligatoire (`AGENTS.md`). Colonne **Tests** : ce qui est testé, rien d'autre — **aucun test ne lance un formateur** (`coding-rules` : hermétiques, pas de binaire externe).

## Vérifié avant M7 (2026-08-27, sur le code de `main` 2bf4f0e et sur les dépôts amont)

**Ce que Wraith a déjà**, relu sur disque :

- `EditorFeature.registerActions()` (`Wraith/Editor/EditorFeature.swift:173`) : une table `(id, titre, raccourci, action)` enregistrée en portée `.tab(kind: EditorFeature.tabKind)` — `editor.format` est **une ligne à ajouter** dans cette table, rien de plus.
- `EditorFeature.active` (`EditorFeature.swift:212`) rend l'onglet actif et son `EditorTab` ; `EditorFeature.save(_:_:force:)` (`:317`) est le point unique de la sauvegarde, appelé par `saveActive()` et `saveAll()` : `formatter.onSave` (R31) s'insère **là**, avant `tab.save(...)`.
- `EditorFeature.insertFinalNewline` (`:294`) lit la section `editor` **à chaque sauvegarde**, sur `workspace.config` — donc sans abonnement à `configChanges()`. La section `formatter` se lit de la même façon : le rechargement à chaud est gratuit, il n'y a rien à câbler.
- `EditorTab` (`Wraith/Editor/EditorTab.swift`) : `textView: NSTextView?` (weak), `currentText`, `isDirty`, `textDidChange()`, `document: FileDocument?`, `save(insertFinalNewline:force:)`, `diskState`.
- `EditorTextView` (`Wraith/Editor/EditorTextView.swift`) crée l'`NSTextView` avec `allowsUndo = true` : l'undo natif est en place, il n'y a qu'à passer par `shouldChangeText(in:replacementString:)` / `didChangeText()` pour que le remplacement soit **une seule opération** annulable (R29).
- `EditorTabView.banners(for:)` et son helper `banner(_:icon:)` (`Wraith/Editor/EditorTabView.swift:50`, `:80`) existent, mais ils sont pilotés **uniquement** par `tab.diskState` et par le document : il n'y a **aucun emplacement pour un message libre**. R28 et R30 en ont besoin → un champ de message transitoire sur `EditorTab`, rendu par le helper existant : **petite API à ajouter**, notée dans la tâche 7.4.
- `TextEditing` (`Wraith/Editor/TextEditing.swift`, `nonisolated enum` de fonctions pures) : `location(ofLine:in:)` est déjà là pour `cmd+l` — c'est ce qui reporte le curseur en ligne/colonne (R29). `lineRange(of:in:)` aussi.
- `FileDocument` (`Wraith/Editor/FileDocument.swift`) : `decode` normalise les fins de ligne en LF, `encode(_:)` restaure les CRLF à l'écriture, `isReadOnly` (lecture seule ou > 2 Mo) — R32 s'appuie dessus, rien à réécrire.
- `AgentCatalog.executables(among names: Set<String>, inPath path: String?) -> Set<String>` (`Wraith/Agents/AgentCatalog.swift:93`) : `static`, pure, cherche des noms dans un `PATH` sans rien lancer. C'est exactement la détection dont R25 a besoin ; elle est **appelée directement** depuis `Editor/` (une feature peut appeler une autre feature, `architecture.md`) plutôt que recopiée. Si un troisième appelant apparaît, elle descendra dans `Workspace/`.
- `Workspace.loginEnvironment() async -> [String: String]` (`Wraith/Workspace/Workspace+LoginEnvironment.swift`) : résolu une fois par fenêtre. `TerminalLaunch.fallbackShell` (`Wraith/Terminal/TerminalLaunch.swift`) donne le repli `/bin/zsh`. `Workspace.resolveLoginEnvironment` montre déjà le montage `Process` + `Pipe` + `waitUntilExit` hors main actor : le lancement du formateur est le même, avec `stdin` en plus.
- **Raccourcis** : `cmd+shift+l` **n'est utilisé par aucune ligne de `shortcuts.md`** (relu ligne par ligne le 2026-08-27) et n'est pas non plus dans la liste « Libres », qui ne le mentionne pas. Il est donc libre côté Wraith. `cmd+opt+l` (le *Reformat Code* d'IntelliJ) est libre aussi, mais la famille `cmd+opt+…` appartient au layout (`layout.focus.*`, `layout.move.*`, `layout.toolbar.toggle`) : mieux vaut ne pas y ajouter une action de feature. La ligne de `shortcuts.md` est à créer et la liste « Libres » à corriger, en 7.1.
- **Dépendances SPM** : M7 n'en ajoute aucune (voir la décision du 2026-08-27) ; le `pbxproj` n'est pas touché.

**swift-format**, lu sur `github.com/swiftlang/swift-format` le 2026-08-27, pas de mémoire : dernier tag `603.0.0` (2026-06-30) ; le manifeste déclare bien un produit **librairie** `SwiftFormat` (en plus de l'exécutable et de deux plugins) ; `SwiftFormatter.format(source:assumingFileURL:selection:to:parsingDiagnosticHandler:)` (`Sources/SwiftFormat/API/SwiftFormatter.swift`) accepte même une `Selection` par plages d'offsets. Dépendances : `swift-syntax` (≥ 602), `swift-markdown` et `swift-argument-parser` — les deux dernières sont déjà dans `Package.resolved`, `swift-syntax` non. **Elle ne formate que du Swift.** Aucune autre librairie de formatage Swift 6 maintenue n'a été trouvée pour les autres langages ; ce qui existe sont les binaires (`prettier`, `black`, `rustfmt`, `gofmt`, `clang-format`), et `AGENTS.md` interdit d'en citer une de mémoire.

## Définition de fini (M7)

- `.wraith/config.json` avec `"formatter": { "ts": "npx --no-install prettier --stdin-filepath file.ts", "swift": "swift format" }` : `cmd+shift+l` sur un `.ts` mal indenté le reformate en moins d'une seconde ; le curseur est resté sur sa ligne ; `cmd+z` annule tout le formatage **d'un seul coup** ; l'onglet est marqué `●`.
- `cmd+shift+l` sur un `.xml` sans entrée : un message le dit, rien ne bouge, aucune erreur.
- Formateur retiré du `PATH` : le message nomme le binaire manquant, pas la plainte du shell ; fichier syntaxiquement invalide : la sortie d'erreur du formateur s'affiche et le texte ne bouge pas.
- `"onSave": true` : `cmd+s` formate puis sauve ; le même `cmd+s` avec un formateur cassé **sauve quand même**, avec la bannière ; `cmd+opt+s` fait pareil sur chaque onglet modifié.
- Un fichier CRLF reste en CRLF sur disque après formatage ; un fichier en lecture seule ou de plus de 2 Mo refuse le formatage avec sa raison ; un markdown en preview aussi.
- Un formateur qui met plus que la borne est arrêté, le texte est intact, et la bannière parle de `formatter.timeout`.
- Modifier la section `formatter` de `config.json` prend effet sans redémarrer (elle est lue à chaque usage, comme `insertFinalNewline`).
- `xcodebuild test` couvre toutes les lignes « Tests » ; **aucun test ne lance un formateur du système** ; lint propre ; **aucune dépendance SPM ajoutée**, `pbxproj` non modifié.
- `docs/specs/editor/01-study-formatter.md` à jour ; `shortcuts.md` : ligne `editor.format` 🟢 ; `editor/questions.md` vidé des deux questions ouvertes de l'étude.

## À trancher pendant M7 (décisions attendues)

- 7.1 : **lib embarquée contre binaire externe** — **tranché (2026-08-27, `editor/decisions.md`) : binaires externes déclarés dans `config.json`.** La seule librairie SPM réelle et maintenue est **swift-format** (`603.0.0`, 2026-06-30, produit `SwiftFormat`, `SwiftFormatter.format(source:…)`), et elle ne formate que du Swift : une des quatorze grammaires de R11, alors que les projets de l'auteur sont en Java, Kotlin et TypeScript. L'embarquer donnerait **deux mécanismes** (une lib pour le Swift, des binaires pour tout le reste) et ajouterait `swift-syntax`, la plus lourde dépendance possible ici. Les binaires, eux, lisent tous `stdin` et écrivent sur `stdout`, et Wraith sait déjà lancer un process avec l'environnement du login shell (`run`, `agents`, `rg`). **Argument contraire à faire valoir si l'auteur en a un** : si le Swift devient le langage majoritaire du workspace et que `swift format` du système est jugé trop lent à démarrer, swift-format en librairie redeviendrait défendable pour ce seul langage — ce serait alors une seconde décision, datée, pas un revirement de celle-ci.
- 7.1 : **`cmd+shift+l`** — proposition : le retenir. Il est libre côté Wraith (vérifié ligne par ligne dans `shortcuts.md`) et n'entre pas dans la famille `cmd+opt+…` du layout. `cmd+opt+l` (IntelliJ) est écarté pour cette raison. Le relevé des conflits avec macOS et les apps tierces de l'auteur est fait en M6 (tâche 6.2) ; s'il tombe, la ligne change là-bas.
- 7.2 : **`formatter.timeout`** (`editor/questions.md`) — proposition : la clé existe dès la v1, défaut 5 s, bornée 1…60. Elle coûte trois lignes et évite une bannière qu'on ne peut pas suivre d'une action.
- 7.4 : **retour quand rien n'a changé** (`editor/questions.md`) — proposition : rien du tout (pas de bannière, pas de bip). Le fichier était déjà formaté ; le silence est le bon retour. À confirmer à l'usage.
- 7.4 : **emplacement du message** — proposition : un champ transitoire sur `EditorTab`, rendu par le `banner(_:icon:)` déjà écrit dans `EditorTabView`, effacé à la frappe suivante. Alternative rejetée : une alerte modale — un formatage raté n'est pas une décision à prendre.
- 7.3 : **tests d'exécution** — proposition : n'exercer le lancement que sur `/bin/cat` (identité : entrée = sortie, code 0) et, si l'auteur l'accepte, `/usr/bin/false` (code non nul, `stdout` vide). Ce sont des binaires POSIX de base, mais ils restent extérieurs au dépôt : si la règle « hermétique » est lue strictement, ces deux tests sautent et seule la fonction pure de décision est couverte.
