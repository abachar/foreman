# M4 — Git

M4 = **voir et valider son travail** : la feature `git` (`Git/`), qui appelle le binaire `git` de l'utilisateur en formats machine. Panneau gauche `git.changes` (`cmd+shift+g`), panneau bas `git.history` (`cmd+shift+h`), onglet central `git.diff`. À la fin de M4, `cmd+shift+g` montre chaque repo du workspace avec sa branche et ses changements, un clic ouvre le diff coloré, `cmd+enter` commite avec les hooks et la signature de l'utilisateur, `cmd+shift+h` déroule le log, et l'explorer porte les badges de statut.

Domaines couverts : [`git`](../specs/git/) ; compléments `explorer` (R4 grisage gitignored, R15 badges) et `editor` (R18 entrées gitignored dans l'index du quick open), tous deux reportés de M1 faute de `Git.statusChanges`.

Colonne **Lib / natif** obligatoire (`AGENTS.md`). Colonne **Tests** : ce qui est testé, rien d'autre — ici, aucun test ne lance `git` ni ne touche au réseau (`coding-rules` : hermétiques) : ce sont les parseurs, la construction d'arguments et les fonctions pures qui sont couverts.

**Workspace** (`Wraith/Workspace/`) :

## Définition de fini (M4)

- `cmd+shift+g` : chaque repo du workspace en section, branche, `↑n ↓m`, changements groupés en Conflicts / Staged / Changes ; le panneau ne lance rien tant qu'il est masqué ; `git commit` fait au terminal se voit en < 1 s.
- Stage, unstage, discard par fichier et par section ; discard demande confirmation en nommant le nombre de fichiers.
- Message + `cmd+enter` : commit passé par les hooks et la signature de l'utilisateur (aucun contournement dans la ligne de commande) ; échec de hook → sortie en bannière et message conservé ; *Amend* pré-remplit le message.
- Clic sur un fichier modifié → diff unifié coloré en aperçu, hunks numérotés, *Stage hunk* / *Unstage hunk* / *Discard hunk* ; double clic fixe l'onglet ; le diff du worktree suit les modifications du fichier.
- `cmd+shift+h` : log `--first-parent` du repo, 200 commits par page, filtre sujet/auteur ; clic → diff du commit ; menu avec checkout, branche, cherry-pick, revert, reset soft/mixed ; `reset --hard` et `push --force` **absents de l'UI**.
- Fetch / pull / push depuis l'en-tête ; une seule opération distante par repo ; un push qui demanderait une authentification interactive donne la bannière avec la commande à copier, jamais de terminal ni de saisie de secret.
- Branches (liste, checkout, création, renommage, suppression, upstream) et stash (push, apply, pop, drop) sans ouvrir le terminal.
- L'explorer colore les fichiers selon leur statut et grise les entrées gitignored ; `cmd+p` ne propose plus les fichiers ignorés.
- `git` absent du `PATH` → bannière unique, le reste de l'app intact ; un repo dont le `status` dépasse 30 s → bannière proposant de le retirer de `config.repos`.
- `xcodebuild test` couvre toutes les lignes « Tests » ; **aucun test ne lance `git`** ; lint propre ; **aucune dépendance SPM ajoutée**, `pbxproj` non modifié.

## À trancher pendant M4 (décisions attendues)

- 4.1 : **`git` R26, résolution du binaire** — proposition : `PATH` du login shell (`Workspace.loginEnvironment()`, déjà résolu une fois par fenêtre pour les agents), surcharge par `git.path` dans la section `git` de `.wraith/config.json` ; la mention « config globale » disparaît de la règle. Cohérent avec la décision config du 2026-08-26.
- 4.2 : **une instance de `GitCLI` par repo ou une par fenêtre** — proposition : une par repo (la spec le dit : les écritures d'un repo se sérialisent entre elles, deux repos n'ont pas à s'attendre) ; le chemin du binaire et sa version sont résolus une fois par fenêtre et passés à chaque instance, pas re-résolus par repo.
- 4.4 : **rendu du panneau changes** — proposition : SwiftUI `List` à sections plutôt qu'un `NSOutlineView` : la hiérarchie est fixe (repo → catégorie → fichier), il n'y a rien de paresseux à charger par niveau, et l'`NSOutlineView` de l'explorer n'a pas de raison d'être copié ici. À revoir si un repo à 5 000 fichiers modifiés rame.
- 4.5 : **portée de `cmd+enter` (commit)** — proposition : le champ de message est un composant natif et `cmd+enter` y est capté comme une touche du champ (comme `cmd+enter` de la palette), pas déclaré au `ShortcutRegistry` : `shortcuts.md` le note `natif`, comme la ligne git actuelle le prévoit déjà. Alternative : une `ShortcutAction` de portée `panel` — rejetée, elle se déclencherait depuis n'importe quel panneau focalisé.
- 4.6 : **rendu du diff** — proposition : `NSTextView` non éditable, un seul `AttributedString` construit par fichier (numéros de lignes en gouttière `NSRulerView` comme l'éditeur, `Highlighter.highlight` par fichier). Alternative : une `List` SwiftUI d'une ligne par ligne de diff — plus simple à écrire, mais la sélection et le copier-coller multi-lignes deviennent maison. À trancher sur un diff de 5 000 lignes.
- 4.6 : **`Highlighter` partagé** — proposition : le créer dans `WorkspaceView` (comme `ThemeService` et `Palette`) et l'injecter à `EditorFeature` et à `Git/` ; c'est le déplacement d'une ligne, conforme à `architecture.md` (services partagés créés une fois dans `App`).
- 4.9 : **liste des branches** — proposition : une feuille de recherche propre à la feature plutôt que la `Palette` partagée : la palette est une fenêtre modale centrée sur l'écran, une liste de branches appartient à la section du repo. À confirmer à l'usage ; la palette reste disponible si le confort manque.
- 4.10 : **fichiers ignorés** (`git/questions.md`) — à mesurer avant de choisir : `status --ignored=matching` en une passe (coût sur un gros repo) ou `check-ignore -z --stdin` sur les seuls dossiers dépliés. Proposition par défaut : `check-ignore` à la demande, parce qu'il suit la paresse de l'explorer (R7 : rien n'est lu avant le dépliage) ; à renverser si la mesure montre que `--ignored` est gratuit.
- 4.4 : **repo supprimé pendant la session** — proposition : la section reste affichée grisée avec la raison jusqu'au prochain rechargement de config, comme un onglet dont le cwd a disparu (`terminal` R16) ; pas de retrait silencieux.
