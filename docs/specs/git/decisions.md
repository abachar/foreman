# git — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-25 | The `git` binary through `Process`, machine formats (`--porcelain=v2 -z`, `--format`) | libgit2 / SwiftGit2 | Hooks, signing, credential helpers, `pull.rebase`… honoured for free; no C to wrap; SwiftGit2 is barely maintained |
| 2026-08-25 | Full scope: status, stage/unstage/discard, commit/amend, per-hunk diff, log, fetch/pull/push, branches, stash | Read-only; stage+commit only | The terminal stays available, but the daily work fits in the panel |
| 2026-08-25 | Every repo stacked as collapsible sections | One repo at a time | An overview of a multi-repo workspace (the main use case) |
| 2026-08-25 | An inline unified diff in a center tab; a linear `--first-parent` log in a bottom panel | Side by side; a branch graph | Enough to review before committing; the graph is a large rendering project |
| 2026-08-26 | The diff colored through the shared `Highlight/` folder (replaces the "no highlighting" decision of 2026-08-25) | tree-sitter imported into `Git/`; +/− diff only | Highlighting is a shared component (`architecture.md`); `Git/` calls it directly |
| 2026-08-26 | `GIT_TERMINAL_PROMPT=0`; an interaction required → a banner with the command to copy, no terminal opened (replaces "switch to a terminal" of 2026-08-25) | Typing credentials into Foreman; an ephemeral terminal surface | No secret in the app (`architecture.md`, security); no free-form shell (`product` R4); the case is rare with a configured helper/SSH agent |
| 2026-08-25 | Discard, drop stash, `-D`, checking out a commit, reset, cherry-pick, revert: confirmed; `reset --hard` and `push --force` absent from the UI | Everything reachable; nothing destructive | The destructive stays explicit; the irreversible stays in the terminal |
| 2026-08-25 | Never an automatic `fetch`; refreshing through FSEvents (worktree + `.git/HEAD`, `index`, `refs/`) | Polling; a periodic fetch | No unrequested network, no disk polling (`architecture.md`) |
| 2026-08-26 | `GitCLI` a concrete type, no `GitService` protocol and no `FakeGitService` | A protocol + a test double | A single implementation (`architecture.md` P1); the parsers are tested over fixtures, the panel over hand-built `GitStatus` values |
| 2026-08-25 | Commit through `-F <temporary file>`, without `--no-verify` and without bypassing the config | The message as an argument; a "skip hooks" option | Safe multi-line messages; the user's hooks are their policy, not ours |
| 2026-08-27 | The `git` binary resolved once per window in the login shell's `PATH` (`Workspace.loginEnvironment()`), overridable by `git.path` in the `git` section of `.foreman/config.json` | A global config key; `/usr/bin/git` hard-coded | The global config was removed on 2026-08-26 (`config`); the login `PATH` is what the agents already use, so the user's Homebrew git wins over Apple's as in their terminal |
| 2026-08-27 | One `GitCLI` instance per repo; the binary's path and version resolved once per window and handed to every instance | One instance per window | A repo's writes serialise against each other, two repos never wait for one another; resolving the binary per repo would repeat the same work |
| 2026-08-27 | The changes panel is a SwiftUI `List` with sections, not an `NSOutlineView` | Copying the explorer's outline view | The hierarchy is fixed (repo → category → file) with nothing lazy to load per level; to be revisited if a repo with thousands of modified files drags |
| 2026-08-27 | `cmd+enter` (commit) is a key of the message field, not a `ShortcutAction` | A `panel`-scoped `ShortcutAction` | A panel-scoped action would fire from any focused panel; the field is native and captures it like the palette does (`shortcuts.md`: `native`) |
| 2026-08-27 | `git.changes` lives in the **right** slot | The left slot, as specified on 2026-08-25 | Seen in use: the author wants the explorer and the changes side by side; the left slot is the explorer's. The right slot is shared with `postgres.schema` (M5), one visible at a time (`layout` R2) |
| 2026-08-27 | The diff is rendered as one SwiftUI `Text` per hunk (an `AttributedString` with the highlighting and the `+`/`−` tint, two gutter texts beside it), inside a scroll view of files | A single non-editable `NSTextView` for the whole diff; a `List` with one row per line | R15 puts buttons on every hunk header and R16 collapses per file: a SwiftUI layout gives both for free, and `Text` keeps native selection and copy within a hunk. To be revisited on a 5,000-line diff |
| 2026-08-27 | One `Highlighter` per window, created in `WorkspaceView` and injected into the editor and `Git/` | A second instance inside `Git/` | `architecture.md`: shared services created once; the parsed grammars are shared |
| 2026-08-27 | The diff is **side by side by default**, inline on demand (R13b); the per-hunk stage/unstage/discard of R15 is **removed** | Inline only (2026-08-25); R15 | The author reads a side-by-side diff faster and does not stage by hunk; the pairing is a pure function over the parsed hunk, nothing else changes |
| 2026-08-27 | The branch list is a **sheet of the feature** with a search field, not the shared `Palette` | The `Palette` | The palette is a modal window centred on the screen; the branch list belongs to the repo's section and carries per-branch actions (rename, delete, upstream) the palette has no room for |
| 2026-08-27 | Ignored entries come with every `status`, through `--ignored=matching` | `check-ignore -z --stdin` on the expanded folders; a full `--ignored` | Measured on the author's repo: 16 ms with or without `--ignored=matching`, 60 ms with `--ignored`; one command, no second mechanism, and the quick open index gets the same table |
| 2026-08-27 | `git.history` shares the **right** slot with `git.changes`: showing one hides the other | The bottom slot (2026-08-25) | Seen in use: the author wants the history where the changes are, not under the editor; `layout` R2 gives the swap for free |

| 2026-08-28 | Session diff base = a tree written from a temporary index (`GIT_INDEX_FILE` + `add -A` + `write-tree`), diffed against a tree rebuilt the same way (`01-study-session-diff.md`) | `git stash create` (no untracked files, touches nothing either); diffing `HEAD` at spawn; copying the worktree | Untracked files are what an agent creates most; the real index is never touched (R29); a commit-less object is enough for `git diff` |
| 2026-08-29 | No repo → no git panels, toggles or shortcuts (R1b, `layout` R36) | An empty Changes panel with "No Repository" | The panel had nothing to offer and its two shortcuts still occupied the home screen; the `ContentUnavailableView` stays for the window where the last repo disappears |
| 2026-08-30 | The Changes panel renders each group (Conflicts, Staged, Changes) as a **tree**, folders with a single child folded into one row; folder rows carry no action | Keeping the flat list; one tree for the whole repo; a list/tree toggle | Use: a repo whose changes span several folders was unreadable flat. Per-group trees keep the existing group actions and the existing row; a toggle would add a setting and a persisted state for a case that solves itself (three files read as three rows) |
| 2026-08-30 (implementation) | The file row's grey line drops the parent folder and keeps only a rename's origin (R6b) | Leaving the parent on the row as R6b first said | The folder rows above the file already spell the parent out; printing `src/main/java` again under `Foo.java` is the flat list the tree replaces |
| 2026-08-30 (from use) | A folder row of the Changes tree **closes and opens** on a click; the fold lives in the view, not in `state.json` (R6b) | A fixed tree, as R6b first said; persisting the fold in `state.json` | Read as fixed, the tree gives no way to put a noisy folder aside. Persisting it would outlive the changes it was hiding, which are gone by the next commit |
