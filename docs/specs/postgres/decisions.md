# postgres — Décisions

| Date | Décision | Alternatives rejetées | Raison |
|---|---|---|---|
| 2026-08-27 | `postgres.schema` par défaut sur **`cmd+shift+b`** ; `cmd+shift+d` reste `layout.split.horizontal` | `cmd+shift+p` ; garder `cmd+shift+d` | Une feature ne peut pas reprendre un raccourci du layout (`layout` R24, vérifié dans `ShortcutRegistry.rebuild` : `reservedByLayout`, l'action n'est pas liée) ; `b` se lit *base*, voisin de `cmd+shift+q`, libre dans `shortcuts.md` et sous macOS ; `cmd+shift+p` reste libre, c'est la palette de commandes ailleurs |
| 2026-08-27 | R10, R17 : **une instruction par exécution** (protocole étendu) ; plusieurs instructions → erreur serveur `42601` expliquée par une bannière | `simpleQuery` (protocole simple) ; tokenizer SQL côté client | PostgresNIO n'expose pas le protocole simple : `PostgresDatabase.simpleQuery` retombe sur `query(_:onRow:)`, donc sur `PostgresQuery(unsafeSQL:)` et le protocole étendu (relu sur 1.33.1) ; le tokenizer maison est déjà rejeté (2026-08-26, `architecture.md` P2) |
| 2026-08-27 | R12, R13 : l'arrêt réel d'une requête passe par `pg_cancel_backend(<pid>)` sur une seconde connexion, en plus de `Task.cancel` | `Task.cancel` seul ; atteindre l'encodeur `internal` de PostgresNIO | `ExtendedQueryStateMachine.cancel()` fait passer le flux en `.drain` : les lignes sont jetées côté client, le serveur continue. `PostgresFrontendMessageEncoder.cancel(processID:secretKey:)` existe mais est `internal` ; `pg_cancel_backend` est du SQL ordinaire |
| 2026-08-27 | Une `PostgresConnection` par fenêtre, pas le pool `PostgresClient` de la lib | Pool `PostgresClient` | Le pool demande une tâche `run()` vivante et n'apporte rien à un consommateur unique (R4 : une connexion par fenêtre) |
| 2026-08-26 | **Une seule connexion par workspace** (`config.postgres` = un objet), pas de sélecteur (remplace « profils nommés » du 2026-08-25) | Profils nommés avec sélecteur | Vision produit : un workspace = une base ; moins d'UI, une seule clé Keychain ; changer de base = éditer la config |
| 2026-08-25 | Mot de passe : Keychain → `~/.pgpass` (0600) → saisie avec enregistrement Keychain | Saisie à chaque fois ; `password` en config | `config` R11 ; `.pgpass` est la convention existante de l'utilisateur |
| 2026-08-25 | Schéma complet par niveau depuis `pg_catalog` (schémas, tables, vues, mat views, fonctions, séquences, types ; colonnes, index, contraintes, FK) | Tables/colonnes seulement ; `information_schema` | Le besoin réel est d'explorer une base inconnue ; `pg_catalog` est rapide et complet |
| 2026-08-25 | Grille lecture seule, autocommit, session `default_transaction_read_only = on` avec toggle d'écriture non persisté | Édition dans la grille ; transactions UI | Outil d'exploration ; l'écriture accidentelle est le vrai risque, l'écriture voulue reste possible |
| 2026-08-26 | Bornes : `LIMIT 500` sur le SQL généré par Wraith ; SQL libre lu en streaming, coupé à 50 000 lignes par annulation de la tâche, avec avertissement ; `statement_timeout` 30 s (remplace « pages par portal » du 2026-08-25) | Portal + `Execute(maxRows)` ; `LIMIT` injecté dans le SQL de l'utilisateur ; tout charger | Utiliser PostgresNIO comme il est conçu (streaming) plutôt que piloter le protocole étendu à la main ; le SQL de l'utilisateur n'est jamais réécrit |
| 2026-08-25 | Export CSV/JSON du résultat chargé ou re-streamé (plafond 1 M lignes) | Pas d'export | Besoin fréquent, coût faible |
| 2026-08-25 | Historique des requêtes dans `.wraith/postgres-history.json` (500, FIFO, épinglage), jamais versionné | Pas d'historique ; dans `state.json` | Fichier dédié pour ne pas gonfler `state.json` ; règle `.gitignore` alignée |
| 2026-08-26 | Éditeur SQL = zone de texte monospace propre à la feature, colorée via le dossier partagé `Highlight/` (remplace « sans highlighting » du 2026-08-25) | Réutiliser l'onglet éditeur de `editor` | L'onglet éditeur est un onglet central, pas un composant de panneau ; le highlighting est un composant partagé (`architecture.md`) |
| 2026-08-26 | Exécution : sélection, sinon **tout le buffer** en une `simpleQuery` ; Postgres découpe les instructions (remplace « instruction sous le curseur » du 2026-08-25) | Instruction sous le curseur avec tokenizer SQL côté client (`'…'`, `$$…$$`, commentaires) | Pas de tokenizer maison (`architecture.md` P2) ; sélectionner ce qu'on veut exécuter couvre le besoin |
| 2026-08-26 | `PostgresClient` type concret, pas de protocole `DatabaseService` ni de `FakeDatabaseService` | Protocole + double de test | Une seule implémentation (`architecture.md` P1) ; les panneaux se testent sur des `QueryResult` construits à la main |
