# editor — Decisions

| Date | Decision | Rejected alternatives | Why |
|---|---|---|---|
| 2026-08-27 | The `stdin` → `stdout` → exit-code contract of R26–R28 is taken from **`format-all-the-code`** (`github.com/lassik/emacs-format-all-the-code`), not invented: its `format-all--buffer-easy` helper states it verbatim and 102 formatter definitions across ~80 languages run on it | Designing our own protocol; a per-formatter adapter in Swift | A contract that has held for eight years over eighty languages does not need to be re-derived; it also settles the awkward cases (a parser inferred from the file name → `--stdin-filepath` in the user's command line, subcommands like `taplo fmt -`) the same way |
| 2026-08-27 | **Formatting through external binaries declared in `config.json`** (`formatter: { "<ext>": "<command>" }`), `stdin` → `stdout`, never a path handed to the formatter | Embedding **swift-format** as an SPM library; doing both | swift-format (`603.0.0`, 2026-06-30, `SwiftFormat` product) only formats Swift, 1 of R11's 14 grammars, and pulls in `swift-syntax`; the other languages only have binaries (prettier, black, rustfmt, gofmt, clang-format), all of them `stdin`/`stdout`. One mechanism, zero dependencies, ~80 lines: Wraith already launches processes this way for `run` and `agents` |
| 2026-08-27 | **Six formatters targeted first** in the study's recommendations and M7's checks: prettier, black, clang-format, dockfmt, sqlformat, swiftformat; the rest of `format-all`'s inventory is kept in the study for later | Recommending one formatter per grammar from the whole inventory; hard-coding the six in the code | They cover the author's languages (TypeScript, JSON, YAML, Markdown, Java, Python, SQL, Swift, Dockerfile) with six binaries; the code stays a command per extension and knows no formatter name, so the list costs nothing to extend |
| 2026-08-27 | **Formatting on save dropped** (R31, US8, M7 task 7.5): `cmd+shift+l` is the only trigger, the `formatter` section has no `onSave` key | Keeping it behind a default-off key | The author does not need it (2026-08-27, during M7); a feature nobody uses is a save path with a formatter in it for nothing |
| 2026-08-27 | `formatter.timeout` exists from v1 (seconds, default 5, clamped 1…60; R30) | Waiting for a slow `npx` to be cut off first | Three lines, and a banner you can act on |
| 2026-08-27 | A formatter that changed nothing gives no feedback (R28, R29): no banner, no beep | A brief status message | The file was already formatted; silence is the right answer, to be confirmed in use |
| 2026-08-27 | The formatter's verdict is a transient `message` on `EditorTab`, rendered by `EditorTabView`'s existing banner helper and cleared at the next keystroke | A modal alert; a status bar | A failed formatting is not a decision to take; the banner slot already existed for the disk state |
| 2026-08-27 | No accepted exit status per entry (R28): exit `0` or nothing is applied | An `exitCodes` key for `tidy` | Only `tidy` is known to need it, and `prettier` covers HTML; revisit if a second formatter needs it |
| 2026-08-27 | Launching is tested over POSIX binaries only (`cat`, `tr`, `false`, `sleep`) under `/bin/sh -l` with an empty `HOME`; no test launches a formatter | No execution test at all | They are the same binaries `resolveLoginEnvironment` relies on; the login shell is `/bin/sh` so nothing of the author's profile runs |
| 2026-08-27 | Two triggers only: `editor.format` (`cmd+shift+l`) and saving when `formatter.onSave` is set; a formatting failure never blocks a save (R31) | Format on type / on paste; formatting the selection; refusing the save when the formatter fails | A simple editor (decision 2026-08-25); losing a save because a binary is missing would be worse than badly indented text |
| 2026-08-27 | The text is replaced in the view as **a single undo operation**, the cursor carried over by line/column (R29) | Rewriting the file on disk and letting R9's reload do the rest | `cmd+z` must undo the formatting in one go; going through the disk would lose the cursor, the `isDirty` state, and would trigger R10's conflict banner |
| 2026-08-27 | No automatic detection of a project's formatter (`.prettierrc`, `pom.xml`, `.editorconfig`) | Reading the tools' configuration files | Same policy as `run` R1: explicit and predictable; the user's command can always point at their own config |
| 2026-08-25 | A simple editor: typing, undo, indentation, in-file find/replace, `cmd+s`; no completion and no LSP | Viewer only; an ambitious editor (LSP, multiple cursors) | Editing a README or a config without leaving Wraith; most code is edited elsewhere |
| 2026-08-25 | `NSTextView` on TextKit 2 | A custom view; TextKit 1 | Undo/IME/accessibility for free; Neon attaches to it directly; to be validated by a prototype |
| 2026-08-25 | A wide set of grammars (java, kotlin, ts/tsx, js, json, yaml, toml, markdown, sql, bash, swift, html, css, dockerfile) | A minimal set (java, ts, markdown, sql) | Adding a grammar = one line of mapping; we may as well cover the daily work |
| 2026-08-25 | Explicit `cmd+s`, no autosave; a silent reload when unmodified, a conflict banner otherwise | Autosave; never reload | Safe with watchers and builds; a known VS Code behaviour |
| 2026-08-25 | Markdown: source/preview toggle inside the tab (`cmd+shift+v`) | Side-by-side synchronised preview | Simplicity; a manual split is there if needed |
| 2026-08-25 | `cmd+p` fuzzy over paths, the index built at the first opening; `cmd+shift+f` content search through `rg` (`grep` fallback) in a bottom panel | Index at startup; a home-made content search; no content search | Laziness (`architecture.md` P4); `rg` is faster and more accurate (gitignore) than anything we would write |
| 2026-08-26 | The palette and the highlighting are shared folders (`Palette/`, `Highlight/`) consumed by the editor; Neon used as is (a highlighter attached to the `NSTextView`), an SPM fuzzy library for the scoring | Home-made fuzzy; a home-made tree-sitter parsing session inside the editor | `architecture.md` P2: `run`, `git`, `postgres` need them too; we do not rewrite what Neon and a fuzzy library do |
| 2026-08-25 | Binaries refused (null byte / extension); > 2 MB read-only without highlighting; > 50 MB refused | Truncated reading | A simple editor does not have to handle large files; refusing beats showing something wrong |
| 2026-08-25 | A file gone at restoration: the tab is ignored (settles the question left by `product`) | An empty read-only tab | Nothing to show; `layout` R28 already provides for it |
| 2026-08-25 | The editor's shortcuts scoped to "the editor tab is active" (the `ShortcutRegistry` supports a scope per tab kind) | Global shortcuts | `cmd+f`/`cmd+s` must not steal anything from a focused terminal |
| 2026-08-27 | Quick open (R17, R18): a byte-wise subsequence pre-filter over lowercased paths kept at indexing, then at most 1,000 candidates scored by FuzzyMatch — file-name matches first, shortest paths first; `DerivedData` on the shared exclusion list; gitignored folders not walked when known | Scoring every path; parallel scoring; a bigger index limit | Measured in M6 6.5: 2 s per keystroke over 53,000 paths (53,000 under `DerivedData/`); FuzzyMatch costs ~40–120 µs per candidate and does not parallelise (contention inside the library, 14 slices = 1 slice). After: ~2 ms here, 0.13–0.23 s on a 16,000-file repo. fzf filters the same way before scoring |
| 2026-08-26 | `Palette/`'s fuzzy library = **FuzzyMatch** (ordo-one, 1.0.0) | Ifrit (a Fuse port); home-made scoring | Fuse is a Bitap for free text, with no boundary bonuses; FuzzyMatch is an fzf/nucleo-style Smith-Waterman (camelCase, `_`, prefix, consecutive characters, ranges), Swift 6, zero dependencies: exactly R17's path scoring |
| 2026-08-26 | **TextKit 2 validated**: Neon's `TextViewHighlighter` on an `NSTextView` with an `NSTextLayoutManager` applies the colors as rendering attributes without falling back to TextKit 1 (test `HighlighterTests`) | TextKit 1 | The prototype planned when M1 was broken down passes; nothing to adapt |
| 2026-08-26 | Neon and SwiftTreeSitter tracked on `main` (no tag), frozen by `Package.resolved`; updating = a dedicated commit | Neon 0.6.0 + SwiftTreeSitter 0.9 | Neon 0.6.0 does not compile with SwiftTreeSitter ≥ 0.10 under Swift 6.2; `main` of both compiles and agrees |
| 2026-08-26 | `sql` removed from R11 in M1, coming back with `postgres` (M5) | Forking the package; a C target in the project | `tree-sitter-sql`'s `Package.swift` (a deprecated `.package(name:)`) does not resolve under Xcode 27; we do not patch a dependency in M1 |
| 2026-08-27 | `sql` stays out of R11 after M5 task 5.4 (plan B): plain text for `.sql` and the SQL editor until upstream fixes its manifest | Forking; a C target; pinning `main` | `v0.3.11` fails resolution (test target names `"SwiftTreeSitter"`, identity `swift-tree-sitter`), `main` still has `.package(name:)`; no dependency patching, the question goes back to `editor/questions.md` |
| 2026-08-26 | css 0.23.2, javascript 0.23.1, yaml 0.7.0 pinned to exact versions | The latest versions | Their recent manifests test `fileExists("src/scanner.c")` relative to the cwd (false under Xcode) and lose the scanner: `external_scanner_*` symbols missing at link time |
| 2026-08-26 | Markdown: the block grammar only (`TreeSitterMarkdown`), not the inline one and no code injections in v1 | Block + inline through `languageProvider` | Enough for `source` mode; the preview (R14) highlights code blocks through `Highlight/` on its own side |
| 2026-08-26 | "Keep open" = `cmd+k` alone | A `cmd+k enter` chord (VS Code) | The `ShortcutRegistry` does not handle chords; adding one for a single action would be over-engineering |
| 2026-08-27 | A gutter with line numbers (a home-made `NSRulerView`, ~80 lines, over the TextKit 2 fragments) | No numbers; a third-party text view (STTextView) | Asked for in use; nothing native numbers TextKit 2, and a third-party text view would replace `NSTextView` for that alone |
| 2026-08-28 | `typescript` and `tsx` (R11) highlighted with tree-sitter-javascript's `highlights.scm` concatenated before their own | Only the package's own queries (what shipped since M1); copying a merged query into the repo | tree-sitter-typescript's queries are written to inherit JavaScript's (35 lines: types and TS keywords only), which SwiftTreeSitter does not do: a `.tsx` file had no strings, comments or functions colored (bug 2026-08-28). Concatenating at load time keeps the upstream queries untouched |
| 2026-08-28 | Code folding from the syntax tree (a node starting with `{`, `[`, `(`), hidden through a custom TextKit 2 layout fragment, not persisted (`02-study-folding.md`) | Indentation folding; `folds.scm` queries (the packages do not ship them); a third-party text view | The tree is already there; TextKit 2's delegate is the platform's way; persisting folds is state nobody asked for |
