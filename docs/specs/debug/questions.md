# Open questions

- [ ] **`java-debug` 0.53.x against `jdtls` 1.62 under JDK 27** (2026-10-17, [00-study.md](00-study.md), technical options): the bundle was last released on 2026-06-26 (0.53.2 on GitHub, 0.53.1 on Maven Central) and `jdtls` 1.62 shipped on 2026-10-01 and needs Java 25 or later; nothing read says they disagree, nothing says they were tried together. M27 27.4 starts by loading the bundle on `ccoe` and asking `vscode.java.startDebugSession` in the log before any UI is written. If it fails, the fallback is `jdtls`'s own JDWP through `org.eclipse.jdt.debug` (shipped in `plugins/`), which has no DAP front and would need the bundle's successor — to settle then, not before.
- [ ] **A shared config carries one machine's paths** (2026-10-17): once `.foreman/config.json` is committed, `lsp.java.settings.bundles`, the Lombok `--jvm-arg`, `-data` and `debug.swift`'s `program` are absolute paths of the author's machine. Expanding `~` and `$HOME` in `lsp` and `debug` commands and in `arguments` is a `config` question (R4's merge of global and workspace files already exists: the machine's paths could live in the global file, the shared file naming only what is the project's). Not `debug`'s to decide.
- [ ] **Hover on a variable while paused** (2026-10-17, out of scope): the popover of `editor` R42 could show `evaluate { expression: <word>, context: "hover" }` instead of the server's hover while a session is paused. Cheap once the session exists; to decide from use.
- [ ] **Exception breakpoints** (2026-10-17, out of scope): `java-debug` and `lldb-dap` both answer `exceptionBreakpointFilters` in their capabilities; a toggle per filter in the panel header is a small task once the panel exists. To decide from use.
- [ ] **Breakpoints in a library source** (2026-10-17, R4; `editor` R63): `java-debug` takes a `jdt://` path in `setBreakpoints`; the library tab would have to carry its URI and the breakpoint store a non-root key. To decide once stepping into Spring has been lived with.
