# M7 — Formatting

M7 = **making the file tidy without leaving the tab**: `cmd+shift+l` formats the active file with the formatter the user declared for that extension, and `formatter.onSave` does it on save. An extension of the `editor` domain, **not a new domain**: no `Formatter/` folder, no feature, no panel — the code lives in `Wraith/Editor/`.

Domain covered: [`editor`](../specs/editor/), study [`01-study-formatter.md`](../specs/editor/01-study-formatter.md) (rules R24–R33, the numbering continued from `00-study.md`).

The **Library / native** column is mandatory (`AGENTS.md`). The **Tests** column: what is tested, nothing else — **no test launches a formatter** (`coding-rules`: hermetic, no external binary).

## Verified before M7 (2026-08-27, on the code of `main` 2bf4f0e and on the upstream repositories)

**What Wraith already has**, re-read on disk:

- `EditorFeature.registerActions()` (`Wraith/Editor/EditorFeature.swift:173`): a table of `(id, title, shortcut, action)` registered with the `.tab(kind: EditorFeature.tabKind)` scope — `editor.format` is **one row to add** in that table, nothing more.
- `EditorFeature.active` (`EditorFeature.swift:212`) returns the active tab and its `EditorTab`; `EditorFeature.save(_:_:force:)` (`:317`) is the single save point, called by `saveActive()` and `saveAll()`: `formatter.onSave` (R31) goes in **there**, before `tab.save(...)`.
- `EditorFeature.insertFinalNewline` (`:294`) reads the `editor` section **on every save**, from `workspace.config` — so with no subscription to `configChanges()`. The `formatter` section is read the same way: hot reloading is free, there is nothing to wire.
- `EditorTab` (`Wraith/Editor/EditorTab.swift`): `textView: NSTextView?` (weak), `currentText`, `isDirty`, `textDidChange()`, `document: FileDocument?`, `save(insertFinalNewline:force:)`, `diskState`.
- `EditorTextView` (`Wraith/Editor/EditorTextView.swift`) creates the `NSTextView` with `allowsUndo = true`: native undo is already in place, and all that is needed is to go through `shouldChangeText(in:replacementString:)` / `didChangeText()` so that the replacement is **a single** undoable operation (R29).
- `EditorTabView.banners(for:)` and its helper `banner(_:icon:)` (`Wraith/Editor/EditorTabView.swift:50`, `:80`) exist, but they are driven **only** by `tab.diskState` and by the document: there is **no slot for a free-form message**. R28 and R30 need one → a transient message field on `EditorTab`, rendered by the existing helper: **a small API to add**, noted in task 7.4.
- `TextEditing` (`Wraith/Editor/TextEditing.swift`, a `nonisolated enum` of pure functions): `location(ofLine:in:)` is already there for `cmd+l` — that is what carries the cursor over by line and column (R29). `lineRange(of:in:)` too.
- `FileDocument` (`Wraith/Editor/FileDocument.swift`): `decode` normalises line endings to LF, `encode(_:)` restores CRLFs on write, `isReadOnly` (read-only or > 2 MB) — R32 leans on it, nothing to rewrite.
- `AgentCatalog.executables(among names: Set<String>, inPath path: String?) -> Set<String>` (`Wraith/Agents/AgentCatalog.swift:93`): `static`, pure, looks names up in a `PATH` without launching anything. That is exactly the detection R25 needs; it is **called directly** from `Editor/` (a feature may call another feature, `architecture.md`) rather than copied. If a third caller appears, it will move down into `Workspace/`.
- `Workspace.loginEnvironment() async -> [String: String]` (`Wraith/Workspace/Workspace+LoginEnvironment.swift`): resolved once per window. `TerminalLaunch.fallbackShell` (`Wraith/Terminal/TerminalLaunch.swift`) gives the `/bin/zsh` fallback. `Workspace.resolveLoginEnvironment` already shows the `Process` + `Pipe` + `waitUntilExit` assembly off the main actor: launching the formatter is the same, with `stdin` added.
- **Shortcuts**: `cmd+shift+l` is **used by no row in `shortcuts.md`** (re-read row by row on 2026-08-27) and is not in the "Free" list either, which does not mention it. It is therefore free on Wraith's side. `cmd+opt+l` (IntelliJ's *Reformat Code*) is free too, but the `cmd+opt+…` family belongs to the layout (`layout.focus.*`, `layout.move.*`, `layout.toolbar.toggle`): it is better not to add a feature action there. The `shortcuts.md` row is to be created and the "Free" list to be corrected, in 7.1.
- **SPM dependencies**: M7 adds none (see the decision of 2026-08-27); the `pbxproj` is not touched.

**`format-all-the-code`** (`github.com/lassik/emacs-format-all-the-code`), read on the upstream repository on 2026-08-27: **102 formatter definitions** for around eighty languages, and its `format-all--buffer-easy` helper states the contract verbatim — *"the program shall read unformatted code from stdin, write its formatted equivalent to stdout, write errors/warnings to stderr, and exit zero/non-zero on success/failure"*. That is R26–R28 exactly. The invocations for every grammar Wraith highlights were taken from its `format-all.el` and are tabulated in the study; two of them shape the tasks below: `AgentCatalog.executables` looks up the **first word** of a command, so `npx --no-install prettier …` is detected as `npx` (correct, and to be covered by a test in 7.2), and `tidy` exits 1 on a mere warning, which R28 rejects (an open question, `prettier` is the recommended HTML entry anyway).

**swift-format**, read on `github.com/swiftlang/swift-format` on 2026-08-27, not from memory: latest tag `603.0.0` (2026-06-30); the manifest does declare a **library** product `SwiftFormat` (alongside the executable and two plugins); `SwiftFormatter.format(source:assumingFileURL:selection:to:parsingDiagnosticHandler:)` (`Sources/SwiftFormat/API/SwiftFormatter.swift`) even accepts a `Selection` by offset ranges. Dependencies: `swift-syntax` (≥ 602), `swift-markdown` and `swift-argument-parser` — the last two are already in `Package.resolved`, `swift-syntax` is not. **It only formats Swift.** No other maintained Swift 6 formatting library was found for the other languages; what exists are the binaries (`prettier`, `black`, `rustfmt`, `gofmt`, `clang-format`), and `AGENTS.md` forbids citing one from memory.

## What is waiting for another milestone

- Formatting `postgres`'s SQL editor (M5) and any other text editor in the app: the `formatter` section will be reusable as it is, but nothing is wired in M7.
- Formatting a selection, format on type / on paste, multi-file formatting, LSP: out of scope for v1 (`01-study-formatter.md`).
- Any clash between `cmd+shift+l` and a system shortcut or a third-party app of the author's: the general survey happens in M6, task 6.2.

## Definition of done (M7)

- `.wraith/config.json` with `"formatter": { "ts": "npx --no-install prettier --stdin-filepath file.ts", "swift": "swift format" }`: `cmd+shift+l` on a badly indented `.ts` reformats it in under a second; the cursor stayed on its line; `cmd+z` undoes the whole formatting **in a single go**; the tab is marked `●`.
- `cmd+shift+l` on an `.xml` with no entry: a message says so, nothing moves, no error.
- Formatter removed from the `PATH`: the message names the missing binary, not the shell's complaint; a syntactically invalid file: the formatter's error output appears and the text does not move.
- `"onSave": true`: `cmd+s` formats then saves; the same `cmd+s` with a broken formatter **saves anyway**, with the banner; `cmd+opt+s` does the same for every modified tab.
- A CRLF file stays CRLF on disk after formatting; a read-only file or one over 2 MB refuses formatting with its reason; so does a markdown file in preview.
- A formatter that takes longer than the bound is stopped, the text is intact, and the banner mentions `formatter.timeout`.
- Editing the `formatter` section of `config.json` takes effect without a restart (it is read on every use, like `insertFinalNewline`).
- `xcodebuild test` covers every "Tests" line; **no test launches a system formatter**; lint clean; **no SPM dependency added**, the `pbxproj` not modified.
- `docs/specs/editor/01-study-formatter.md` up to date; `shortcuts.md`: the `editor.format` row 🟢; `editor/questions.md` cleared of the study's two open questions.

## To decide during M7 (decisions expected)

- 7.1: **an embedded library versus an external binary** — **settled (2026-08-27, `editor/decisions.md`): external binaries declared in `config.json`.** The only real, maintained SPM library is **swift-format** (`603.0.0`, 2026-06-30, product `SwiftFormat`, `SwiftFormatter.format(source:…)`), and it only formats Swift: one of R11's fourteen grammars, while the author's projects are in Java, Kotlin and TypeScript. Embedding it would give **two mechanisms** (a library for Swift, binaries for everything else) and would add `swift-syntax`, the heaviest possible dependency here. The binaries all read `stdin` and write to `stdout` — a contract `format-all-the-code` has run on for eight years across 102 formatter definitions — and Wraith already knows how to launch a process with the login shell's environment (`run`, `agents`, `rg`). **A counter-argument to raise if the author has one**: if Swift becomes the workspace's dominant language and the system's `swift format` is judged too slow to start, swift-format as a library would become defensible again for that language alone — that would then be a second, dated decision, not a reversal of this one.
- 7.1: **`cmd+shift+l`** — proposal: keep it. It is free on Wraith's side (verified row by row in `shortcuts.md`) and does not sit in the layout's `cmd+opt+…` family. `cmd+opt+l` (IntelliJ) is ruled out for that reason. The survey of clashes with macOS and with the author's third-party apps happens in M6 (task 6.2); if it falls, the row changes there.
- 7.2: **`formatter.timeout`** (`editor/questions.md`) — proposal: the key exists from v1, default 5 s, clamped to 1…60. It costs three lines and avoids a banner you cannot act on.
- 7.4: **feedback when nothing changed** (`editor/questions.md`) — proposal: nothing at all (no banner, no beep). The file was already formatted; silence is the right feedback. To be confirmed in use.
- 7.4: **where the message goes** — proposal: a transient field on `EditorTab`, rendered by the `banner(_:icon:)` already written in `EditorTabView`, cleared on the next keystroke. Rejected alternative: a modal alert — a failed formatting is not a decision to take.
- 7.3: **execution tests** — proposal: exercise the launching only over `/bin/cat` (identity: input = output, code 0) and, if the author accepts, `/usr/bin/false` (a non-zero code, empty `stdout`). They are basic POSIX binaries, but they still live outside the repository: if the "hermetic" rule is read strictly, those two tests go away and only the pure decision function is covered.
